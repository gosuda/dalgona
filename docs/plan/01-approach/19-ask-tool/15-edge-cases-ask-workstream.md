#### Edge cases (ask workstream)

- If the model's arguments fail validation, the call completes `ok=false` with the `ask:` message, and the loop guard (4 identical calls) still applies.
- A plugin hook can deny `ask` like any other call. In mode `auto` or `ask`, class `read` accepts mechanically (`docs/spec/approvals.md` step 3).
- If resolution arrives before the request, retain that resolved identity and suppress the late card. A stale warning or response must not reopen it.
- A steer or follow-up typed in the browser while a question is open is delivered by the existing steer rules once the tool returns. In the terminal, the card holds the keys.
- If the thread closes during a wait, the outcome is interrupted. If the completion append then fails, recovery applies the D3 row.
- Typed answers pass through the secret masker like any tool output (`tools.go:417-420`).
- `ask` retains `Serial: true` in its tool specification. Calls run alone rather than relying on the generic read-class batching rule.
- An otherwise valid answer envelope containing invalid text stays pending. It cannot consume the first-valid-answer decision or reset the deadline.
- Blank required model fields fail before offer. User whitespace-only answers retain their distinct accepted value.
- An offered label with spaces or CRLF returns unchanged. Only newly authored free-form text uses the interactive newline adapter.
- The five-minute timeout races answers through the host's single outcome owner. A non-ask consumer treats timeout as no answer.
