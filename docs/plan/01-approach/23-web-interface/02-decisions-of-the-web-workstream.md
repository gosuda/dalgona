#### Decisions of the web workstream

| Decision | Rejected rival | Reason |
|---|---|---|
| Component tests run in Vitest with `happy-dom` 21.0.4 and `@testing-library/svelte` 5.4.2, in a second Vitest project named `dom` (files `*.dom.test.ts`). Pure logic stays in the `unit` project (node). | `jsdom` 31.0.0; Vitest browser mode (`@vitest/browser-playwright` 5.1.0) | jsdom has no `HTMLDialogElement.showModal` (jsdom issue #3294) and needs Node ^22.22.2. Browser mode downloads Chromium during `just verify`, which breaks offline installs. |
| Layout, sticky positioning, forced colours, loaded fonts, motion and target size are proven by browser checks in `web/checks/*.js`, which the live-debug workstream runs in a real browser. Each check returns `{ok, failures}`. | Real-browser checks inside `just verify` | A DOM emulator cannot measure layout. The live-debug workstream already owns a browser and a scripted model server. |
| The palette is TypeScript data (`web/src/lib/theme/palette.ts`). `installTokens` writes it as CSS custom properties into a `<style id="dalgona-tokens">` element at startup. Values are copied from `DESIGN.md`. | A hand-written `tokens.css` | With data, a unit test can check WCAG contrast for every theme without asserting on source text. |
| `theme = auto` and `theme = auto-soft` are pure CSS (`prefers-color-scheme`): `auto` resolves to `night` or `day`, and `auto-soft` to `soft-night` or `soft-day` (Design record, Colour). An explicit theme is cached in `localStorage["dalgona.theme"]` and applied before mount. | An inline boot script in `app.html` | The boot script would be a second copy of the theme logic. CSS and the theme apply in the same frame, because the CSS loads with the JavaScript bundle. |
| Markdown: `marked` 18.2.0, then `dompurify` 3.4.17. Code: `highlight.js` 11.12.0 core with a fixed language set, coloured through class names mapped to tokens. | `markdown-it` 15.0.3; `shiki` 4.6.0 | markdown-it needs the same sanitiser and is larger. shiki writes inline colours from its own themes, does not follow our four themes, and ships a heavy grammar engine. |
| Model output is untrusted: raw HTML in Markdown renders as escaped text; the sanitiser allows only a tag and attribute list; links keep only `http:`, `https:` and `mailto:`; there are no images. `Markdown.svelte` holds the only `{@html}` in the code. | Trusting marked output, or allowing images | Markdown can carry script, event handlers and `javascript:` URLs. Images can leak data through their requests. |
| Schema conformance is checked at test time with `ajv` 8.20.0 against `internal/rpc/testdata/codex-schema` and the `dalgona/` schemas in `internal/rpc/testdata/dalgona-schema`. Each parser rejects a payload that misses any member the schema requires. | Running ajv in the browser | The full schema is 650 KB, and validating each delta would sit on the hot path. The Go tests already check server output against the same schema. |
| Every pending request (approval, question or sandbox choice) becomes an inline card in the dock, above the composer. Its details scroll; its action row does not. | Keep the modal `<dialog>` and make the actions sticky | The user judges the action against the transcript, and the terminal also shows an inline card. Placing the actions outside the scroll box needs no sticky trick. |
| Page state moves into `class Session` in `web/src/lib/session.svelte.ts`. `+page.svelte` renders `App.svelte`. | Keep about 570 lines of state in `+page.svelte` | Tests need to drive approvals, questions, notices and panels through a fake RPC port. `+page.svelte` cannot take a test session. |
| Fonts: `@fontsource-variable/bricolage-grotesque` 5.3.0 and `@fontsource-variable/hanken-grotesk` 5.3.0 (normal and italic), plus `pretendard` 1.3.9 through `dist/web/variable/pretendardvariable-dynamic-subset.css`. | Static weight files; a font CDN | Variable fonts cover every weight in one file. A CDN breaks offline and LAN use and leaks requests. |
| Hangul loading: Hanken Grotesk comes first in the text stack and Pretendard Variable second. Pretendard's 92 `unicode-range` subsets (2.96 MB in total) load only for the glyphs a page uses. Prose uses `word-break: keep-all`. | Loading the full 2.06 MB Pretendard file | The full file costs every reader 2 MB. With unicode ranges, Latin text never fetches Pretendard. |
| Code face is `ui-monospace, SFMono-Regular, Menlo, Consolas, monospace` (Design record, Type for the web) | `monospace, monospace` | The owner chose the Design record, Type for the web stack, which ends in the reader's `monospace`. The earlier doubled name targeted a Chrome 13 px quirk that this run did not verify. |
| The follow-up key is Alt+Enter, as in the terminal (`internal/tui/model.go:200-201`). | Keep Ctrl or Cmd+Enter (`Composer.svelte:64`) | One visual and key system for both surfaces. |
| Reduced motion follows only `prefers-reduced-motion`. The browser does not learn `DAL_NO_MOTION` from the daemon. Under the media query, the live dot is static and the elapsed counter updates only when the transcript changes. | A daemon setting sent to the browser | `DAL_NO_MOTION` belongs to the terminal process, and the browser has its own setting. |
| Keyword matches show as underlined text plus a plain `Keywords: <words>` line. `keywordGradient` is deleted. | Keep the gradient sweep | The sweep carries meaning by colour alone, and the terminal spec forbids colour as the only signal (`docs/spec/tui.md:35`). |
| Paste at the terminal workstream's threshold (Step 28) becomes a chip. On send, the pasted blocks follow the typed text, separated by blank lines, in paste order. | Inline chips inside the textarea | A textarea cannot hold inline widgets. |
| Remove the runner segment from the status band | Keep showing `local` | The server sends no runner value (`validation.ts:180-186`), so the client invents it. |
| Desktop notifications fire only when the tab is hidden and the user has granted permission from Settings. The document title always carries the state word. | Asking for permission on load | Browsers block a permission request that has no user gesture. |
| `!` shell mode follows the terminal workstream, Step 30 (cross-phase decision 14). | Always `sh -c` | The daemon may run on Windows. |
| Copy: `Start thread`, `Send`, `Steer`, `Queue follow-up`, `Interrupt`, `Accept`, `Accept for session`, `Decline`, `Cancel and interrupt`, `Thinking`, `Dismiss`. | Keep the current labels | Actions start with a verb. Cancel must say that it interrupts, as the terminal says at `model.go:715`. "Thinking" is the row name; the model item stays "Reasoning" in the data. |
| The point (Design record, The point and the thread hue) and the thread hue (Design record, The point and the thread hue) | Several filled buttons per view | One solid fill per view keeps the eye on the next action, and the hue ties it to its thread. |
| `StateTag` fills only when it holds the point | Every live tag filled | Design record, The point and the thread hue allows one fill per view, and a live tag in the list would compete with the point. |
| The retry line (cross-phase decision 41) is plain text, not a live region | Announce every countdown tick | A line that changes each second would flood a status region, so the status region announces the wait once. |
| Helpers with one caller and no test of their own fold into that caller (see the abstraction pass) | One named helper each | A helper that does not make its caller easier adds a name and an export. `acceptThreadStatus` stays: it is the only unit-testable seam before step 4. |
| `Panel` is created in step 18 and `ReviewView` uses it from the start | A native `<dialog>` in step 18, replaced in step 28 | Two layers for one caller in sequence would be rewritten within two steps. |
| Browser panels take the ruled-ledger card rules (Design record, Browser cards) | The terminal open rail (Design record, Terminal panels) | Design record, Components gives the open rail to terminal panels only. The browser choice is final in this plan. |

Conventions for every step:
- Vitest project `unit` runs `src/lib/**/*.test.ts` except `*.dom.test.ts`. Project `dom` runs `src/lib/**/*.dom.test.ts` in happy-dom.
- "Fails before" names the defect or the missing behaviour that makes the test red on the parent commit.
- Each step ends with `just verify` green.
- Spec edits go to `docs/spec/web.md` unless stated otherwise.
- Keep every function below cyclomatic complexity 10. Dispatch over unions through `Record` maps, not long switches.
- `tsconfig.json` sets `isolatedDeclarations`, so annotate the type of every exported binding.
- `primary` in the steps below means the point (Design record, The point and the thread hue): one solid fill per view. `App` picks the holder in this order: the primary action of the shown request (cross-phase decision 26: one request at a time, oldest first) or the open panel, since a panel is a view; else the open thread's live `StateTag`; else Send; on the empty view, Start thread. Every other button is `quiet`. While a turn runs, the live tag holds the point, so Steer is `quiet`.
- Thread hue (Design record, The point and the thread hue): `threadHue(id)` in `web/src/lib/hue.ts` (step 11). The App root carries `data-hue` for the open thread. The empty view uses `threadHue("")`, which is 1.
