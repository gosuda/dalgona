### Bubble Tea practice

1. Program: `tea.NewProgram(model, tea.WithContext(ctx), tea.WithEnvironment(env), tea.WithInput(in), tea.WithOutput(out), tea.WithFPS(framesPerSecond))`. The dock is inline: `View.AltScreen` stays false. The full-screen review sets `View.AltScreen = true` inside `View()` while it is open. No command toggles a screen mode.
2. `View()` returns `tea.View`. Cursor, window title, focus reporting, mouse mode and program status are fields of that value, set in `View()` only.
3. Mouse mode is `tea.MouseModeNone` while the dock shows, so that the terminal keeps selection and scrollback. It is `tea.MouseModeCellMotion` only while the full-screen review or a list panel is open. `View.MouseMode` is set in `View()` only (`bubbletea/v2@v2.1.1/tea.go:189-191`, `tea.go:297-319`).
4. The frame has at most `screen.height - 1` lines, and each line is at most `screen.width - 1` cells. Bubble Tea drops the top rows of a taller inline frame (`bubbletea/v2@v2.1.1/cursed_renderer.go:353-357`). A panel that needs more rows scrolls inside itself.
5. A finished block goes to scrollback once, through `commit`, and `drain`, which `Update` calls, returns `tea.Println`. Bubble Tea writes that text verbatim (`cursed_renderer.go:771-830`), so the client first passes it through `colorprofile.Writer{Forward: &buf, Profile: p}` (`colorprofile@v0.4.3/writer.go:37-50`). `p` comes from `tea.ColorProfileMsg`. It starts as `colorprofile.ASCII`, never the zero value `Unknown`, which strips bold as well. Every printed line is at most `screen.width - 1` cells, and one `tea.Println` holds at most `screen.height` minus the dock height in lines. The first print is the welcome row, on success or on error, and `View()` is empty until it has printed (print rule 5). Rows that finish while the review is open are held and printed when it closes. A printed row is never printed again and never rewrapped.
6. `Update` and `View` do no I/O. I/O runs in a `tea.Cmd` and returns a message. Nothing calls `Program.Send` from inside `Update`: the message channel is unbuffered (`tea.go:620`, `tea.go:1211-1220`). One goroutine, the RPC reader, calls `Program.Send`.
7. One tick chain drives the motion of the dock: `spinner.Model` from `charm.land/bubbles/v2/spinner`, whose tick carries a tag and whose `Update` rejects a stale tag (`bubbles/v2@v2.2.1/spinner/spinner.go:124-157`). The chain stops when nothing moves. Under `DAL_NO_MOTION` the same chain runs at one second and changes only the elapsed field and the rate-limit countdown. The dot stays on its first frame. One chain drives every change, so no second chain runs for the countdown.
8. Elapsed time is computed in `View()` from a start instant. It needs no timer of its own.
9. Keys are matched as `tea.KeyPressMsg` with `key.Binding` and `key.Matches` from `charm.land/bubbles/v2/key`. The space key is `"space"`. Printable text comes from the `Text` field of the key. No code compares raw runes or the string `" "`.
10. A paste arrives as one `tea.PasteMsg`. The client normalises CRLF to LF, cleans the text, and inserts it once.
11. The editor is hand-written in `internal/tui/input.go`: `charm.land/bubbles/v2/textarea` has no paste chip, which the editor needs. The cursor is the terminal's own: `View.Cursor = tea.NewCursor(x, y)` in frame coordinates, with `Blink` set from the motion setting (`bubbletea/v2@v2.1.1/tea.go:385-401`). `View.Cursor` is never nil while the client is inline, and its row is in the composer, which is the first part of the dock. The client draws no cursor glyph.
12. The background colour comes from `tea.RequestBackgroundColor` in `Init` and the `tea.BackgroundColorMsg` reply. No code calls `lipgloss.HasDarkBackground` from `Update` or `View`: it does blocking terminal I/O (`lipgloss/v2/query.go:12-13`).
13. The colour profile comes from `tea.ColorProfileMsg`. The client reads `NO_COLOR` itself: any non-empty value sets the profile to `colorprofile.ASCII`, which keeps bold, underline and reverse. `colorprofile.Detect` honours `NO_COLOR` only when the value parses as true and only on a terminal (`colorprofile@v0.4.3/env.go:33-44`, `:86-88`, `:113-118`).
14. A capability query is `tea.RequestCapability(name)`. The reply is `tea.CapabilityMsg`. Its `Content` is the hex-decoded name, or `name=value` when the reply has a value, and several are joined with `;` (`ultraviolet/decoder.go:1795-1830`, `bubbletea/v2@v2.1.1/termcap.go:43-45`). A terminal that does not answer sends nothing.
15. Width is measured with `cells`, cut with `fit` and wrapped with `wrap` of `internal/tui/width.go`, which use the renderer's own method (cross-phase decision 57). No code workstreams a styled string by bytes, and no code calls `lipgloss.Width`, `ansi.StringWidth` or `ansi.Truncate` directly for a dock row or a printed row.
16. `tea.WindowSizeMsg` recomputes the dock for the new width. Finished rows are left to the terminal. The client returns no `tea.ClearScreen`, in any case.
17. In the update that starts a quit or a suspend, the model sets `m.leaving`, and `View()` then returns one blank row with `ProgramStatus` set to `&tea.ProgramStatus{State: tea.ProgramStateIdle}`. The renderer erases from the last row of the last view, so an empty last view would erase the last history row (`bubbletea/v2@v2.1.1/cursed_renderer.go:201`). The exit row is printed like any finished row, and `tea.Quit` follows after the last print has landed (print rules 2 and 3). An open review closes first.
18. Nothing else writes to the terminal while `Run` is active.
19. `ctrl+z` calls `suspend()` (Terminal step 13), which sets `m.leaving` and `m.suspending` as in rule 17. `finishSuspend` returns `tea.Suspend` (`bubbletea/v2@v2.1.1/tea.go:586`) only when no print is in flight and no row waits, or when the window height is 0 (Terminal step 13). `tea.ResumeMsg` (`bubbletea/v2@v2.1.1/tea.go:600`) clears `m.leaving`, and the dock is drawn at the cursor's new line.
20. No planned feature runs a program on the terminal. `tea.ExecProcess` is not used.
21. A desktop notification is a raw OSC sequence returned through `tea.Raw`. It is sent only when the window is not focused, from `tea.FocusMsg` and `tea.BlurMsg` with `View.ReportFocus = true`.
22. Tests drive `Update` with message values and assert on model fields and on `View().Content`. A program-level test uses `tea.WithInput`, `tea.WithOutput`, `tea.WithWindowSize`, `tea.WithColorProfile` and `tea.WithoutSignals`. No test compares a saved full frame.
23. `Run` keeps its panic recovery. A goroutine that the client starts recovers its own panic and asks the program to quit.
24. `View()` costs the size of the dock. It never rebuilds the transcript.
25. A glamour renderer is kept for each width and theme, and one lock guards each renderer. `glamour.NewTermRenderer` with no options has an empty style (`glamour/v2@v2.0.1/glamour.go:68-105`), so the client passes its styles with `glamour.WithStyles` (`glamour.go:146-149`).
26. The client sets no `tea.WithFilter`. Wheel scrolling comes from `viewport.Model` in the review and from the list panel.
27. Every line of `View().Content` and every printed row is at most `width - 1` cells by `cells`. A glyph in a fixed field has East Asian Width `N`, `Na` or `H`.
