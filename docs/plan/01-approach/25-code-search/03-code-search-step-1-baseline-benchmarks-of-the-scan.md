#### Code search step 1. Baseline benchmarks of the scan path

Anchor: John Carmack, Richard Feynman

This step adds benchmarks and one workload test. It changes no product code. The benchmarks measure today's code at commit `3c4b6f94`, before any index code exists. Each hypothesis is labelled `[unmeasured]`. Their output is the baseline for the index steps.

- Files: new `internal/tool/search/bench_helpers_test.go`, `bench_workload_test.go`, `bench_ignore_test.go`, `bench_walk_test.go`, `bench_scan_test.go`, `bench_collect_test.go`, `bench_render_test.go`, `bench_codec_test.go`, `bench_run_test.go`, `bench_glob_test.go`; new `internal/tool/snapshot/capture_bench_test.go`; new `internal/tool/read/bench_read_test.go`.
- Helper: `func writeWorkload(tb testing.TB, root string, files, bytesEach int, seed uint64) []string` in `bench_helpers_test.go`. It writes `files` regular files named `d%03d/f%05d.txt`, where the directory index is `i % 200` and the file index is `i`. Each file holds `bytesEach` bytes from the alphabet of lowercase letters, space and newline, drawn from `rand.New(rand.NewPCG(seed, 2))`. It returns the relative paths in sorted order.
- Tests that fail before the change (compile failure, because `writeWorkload` does not exist yet):
  - `TestWriteWorkloadShape` in `bench_workload_test.go`. Input: `files` 2000, `bytesEach` 10000, seed 1. Expected: 2000 paths, each file 10000 bytes, total 20000000 bytes. Source: the workload A definition of this step.
  - `TestWriteWorkloadIsSeeded` in `bench_workload_test.go`. Input: the same call twice with seed 1, `files` 3, `bytesEach` 64. Expected: the two runs write byte-equal files. Source: the seeded generator rule of this step.
- Common rules for every benchmark in this step:
  - Metric: samples are recorded per call inside the loop and reported with `b.ReportMetric` as `p50_ns`, `p95_ns`, `p99_ns` and `max_ns`. `b.ReportAllocs` gives allocs/op and B/op.
  - Workload A: 2000 files of 10000 bytes from `writeWorkload` in `b.TempDir()`. Workload B: 200,000 files and 4 GB of text, generated once into the directory named by the environment variable `DALGONA_SEARCH_BENCH_CORPUS`. Without that variable, workload B calls `b.Skip`.
  - Repetitions: `go test -run '^$' -bench <name> -benchmem -count=10`. `benchstat` at its default alpha of 0.05 compares baseline and variant runs from the same session.
  - Noise controls: the `GOMAXPROCS` value given per item, an idle host, the runs directory and the workspace on one filesystem, and no other test running.
  - Baseline commit: `3c4b6f94`. The project projection in `internal/tool/project.go:9-27` is excluded.
- Benchmarks. Variants are described only.
  1. `BenchmarkIgnoredFileDirOnlyRules` in `bench_ignore_test.go`. Hypothesis [unmeasured]: each file costs one `hasIgnoredParent` call for each directory-only rule, and each call builds ancestor prefixes (`internal/tool/search/ignore.go:102`, `ignore.go:110`). Baseline: `loadIgnore(root).ignored(root, p, false)` (`ignore.go:85-98`). Workload: a root `.gitignore` with 40 lines `name%02d/` and 10 plain names; 200,000 relative paths of depth 3 to 8 built in memory from `rand.NewPCG(1, 2)`; the stack loads outside the timer. `GOMAXPROCS=1`, count 10, no disk access in the timed loop.
  2. `BenchmarkIgnoredRuleStack` in `bench_ignore_test.go`. Hypothesis [unmeasured]: the cost of `ignored` grows with every rule loaded so far (`ignore.go:87-88`, `ignore.go:55`). Metric: ns per path, and the slope of ns per path against R. Baseline: `ignoreStack.ignored`. Workload: R = 10, 100, 1000 and 10000 rules; R/5 subdirectories, each holding a 5-rule `.gitignore` from `rand.NewPCG(1, 2)`; 10,000 fixed paths in the last directory. `GOMAXPROCS=1`, count 10.
  3. `BenchmarkWalkScopeFind` in `bench_walk_test.go`. Hypothesis [unmeasured]: `contained` calls `filepath.EvalSymlinks` for each regular file (`internal/tool/search/engine.go`, method `contained`), so each file costs one Lstat per path component. Baseline: `execute(root, args)` in find mode with pattern `no-such-name` and limit 1. The setup of `par_test.go:46-49` is grep with pattern `hit` and limit 1000, and there is no find call there. Workload: 20,000 files in 2,000 directories of depth 6 to 8. Warm-up: one untimed walk. `GOMAXPROCS=1`, count 10. The Lstat count comes from `strace -f -c -e trace=newfstatat,lstat`, run by the operator.
  4. `BenchmarkWalkSortOnly` in `bench_walk_test.go`. Hypothesis [unmeasured]: the `SortFunc` call in `walkScope` sorts every entry before `find` keeps the first `limit` paths. Baseline: that sort on a seeded shuffle of 200,000 `fileEntry` values. Warm-up: one untimed sort. `GOMAXPROCS=1`, count 10.
  5. `BenchmarkWalkStatPass` in `bench_walk_test.go`, sub-benchmark `walk`. Hypothesis [unmeasured]: the walk alone is a fixed share of each call on workload B. Baseline: `walkScope(root, root)`. Workloads A and B. Warm-up: one untimed walk. A cold-cache run happens only when the operator writes 3 to `/proc/sys/vm/drop_caches` before each sample (outside check). `GOMAXPROCS=1`, count 10. The sub-benchmark `planReads` joins this function in step 4.
  6. `BenchmarkScanFileMatchAll` in `bench_scan_test.go`. Hypothesis [unmeasured]: `scanFile` runs the regular expression once per line (`engine.go`, function `scanFile`), and `splitStarts` walks each byte. Baseline: `scanFile` with `regexp.MustCompile("e")`, written in the test as the pattern `e`. Workload: 150 files of 100 KB with lines of 40 to 100 bytes, from `rand.NewPCG(1, 2)`. The metric adds MB/s from `SetBytes`. `GOMAXPROCS=1`, count 10.
  7. `BenchmarkReadCappedLarge` in `bench_scan_test.go`. Hypothesis [unmeasured]: `readCapped` copies a 16 MiB file through the growth of `io.ReadAll`, and `searchableText` runs `utf8.Valid` over every byte (`engine.go`, functions `readCapped` and `searchableText`). Baseline: `readCapped`. Workload: a 16 MiB text file from `rand.NewPCG(1, 2)`. `GOMAXPROCS=1`, count 10.
  8. `BenchmarkCollectMatchesRetention` in `bench_collect_test.go`. Hypothesis [unmeasured]: `collectMatches` keeps the bytes and line starts of every matching file until rendering (`engine.go`, function `collectMatches`). Baseline: `collectMatches(files, re, 200)`. The metric adds heap in use after the call, from `runtime.ReadMemStats`. Workload: 4,000 files of 64 KiB, half of them matching. Warm-up: one untimed call, and `runtime.GC()` before each sample. `GOMAXPROCS=8`, count 10.
  9. `BenchmarkRenderGrepManyFiles` in `bench_render_test.go`. Hypothesis [unmeasured]: `lineMarks` allocates a map and loops over every kept hit for each scanned file, and `appendFileRows` loops over every line (`engine.go`, functions `lineMarks` and `appendFileRows`). Baseline: `renderGrep`. Workload: 50,000 `grepFile` values from 2 KB files, with 1,000 hits spread over them, all built outside the timer. `GOMAXPROCS=1`, count 10.
  10. `BenchmarkSnapshotCaptureHashing` in `internal/tool/snapshot/capture_bench_test.go`. Hypothesis [unmeasured]: `makeResult` hashes the captured file three times and copies it once (`internal/tool/search/search.go`, function `makeResult`, and `internal/tool/snapshot/store.go:123-124`, `tag.go:10`, `tag.go:18`). Baseline: `Capture`, `Tag` and `VersionTag`. Workload: 16 MiB of text, with `SetBytes(16 << 20)`. `GOMAXPROCS=1`, count 10. The SHA extension flags are recorded from `/proc/cpuinfo`.
  11. `BenchmarkSearchOutcomeCodec` in `bench_codec_test.go`. Hypothesis [unmeasured]: the reply carries each capture as base64 inside JSON, and each decode step copies the value again (`internal/tool/search/json.go`, functions `encodeOutcome` and `decodeOutcome`). Baseline: `encodeOutcome` and `decodeOutcome`. Workload: 200 text rows and one 16 MiB capture with 200 shown ranges, from `rand.NewPCG(1, 2)`. The metric adds MB/s from `SetBytes(len(encoded))`. `GOMAXPROCS=1`, count 10.
  12. `BenchmarkSearchToolLargeOutput` in `bench_run_test.go`. Hypothesis [unmeasured]: each poll returns at most one 1 MiB page (`internal/runner/wire.go:24`), and `collect` waits 5 ms between polls (`internal/tool/search/search.go`, function `collect`). A reply of about 21 MB needs about 20 polls. Baseline: `Tool.Run`. Workload: `runner.NewLocal(filepath.Join(b.TempDir(), "runs"))` with `Sandbox{Mode: runner.SandboxOff}` and a 16 MiB seeded file. Arguments: grep for `line` with limit 200. Warm-up: one untimed run. `-benchtime=100x`, count 10, `GOMAXPROCS=8`. Read calls come from a counting wrapper. The write count comes from `strace -f -c -e trace=write`, run by the operator.
  13. `BenchmarkSearchToolSmallFind` in `bench_run_test.go`. Hypothesis [unmeasured]: each call starts two processes (`internal/runner/local.go:97`, `internal/runner/shim.go:108`) and waits on a 5 ms step (`collect` in `search.go`). Baseline: `Tool.Run`. Workload: 1,500 files, 15 MB in total. Arguments: find with pattern `file-00042.txt`. The test binary is the child (`internal/tool/search/main_test.go:10`). Warm-up: one untimed call. `-benchtime=100x`, count 10, `GOMAXPROCS=8`. The exec count comes from `strace -f -e trace=execve`, run by the operator.
  14. `BenchmarkReadToolWindowMiddle` in `internal/tool/read/bench_read_test.go`. Hypothesis [unmeasured]: `read` reads the whole file with `io.ReadAll` (`internal/tool/read/read.go:139`), splits all lines (`read.go:254`), and hashes the file three times (`read.go:215-216`). Baseline: `Tool.Run`. Workload: `big.txt` with 100,000 lines of 40 bytes from `rand.NewPCG(1, 2)`; the call reads offset 50000, limit 200. Warm-up: one untimed run. `GOMAXPROCS=1`, count 10.
  15. `BenchmarkReadToolSmallFiles` in `internal/tool/read/bench_read_test.go`. Hypothesis [unmeasured]: each read calls `filepath.EvalSymlinks` on the workspace and on the target (`read.go:289`, `read.go:293`), and `openat2` checks containment again (`internal/runner/readpin_linux.go:31`). Baseline: `Tool.Run`. Workload: 1,500 files of 2 KB at depth 6; each iteration reads one of 200 seeded paths. Warm-up: one untimed pass. `GOMAXPROCS=1`, count 10.
  16. `BenchmarkMatchingFilesAll` in `bench_glob_test.go`. Hypothesis [unmeasured]: grep runs `matchingFiles` on every call with `cmp.Or(args.Glob, "**")` (`internal/tool/search/engine.go:211`), so `**` is used only when no glob is given, and the compiled expression runs for each entry (`internal/tool/search/glob.go:88`). Baseline: `matchingFiles(entries, "**")`, where the declaration is `internal/tool/search/engine.go:273`. Workload: 200,000 `fileEntry` values with relative paths from `rand.NewPCG(1, 2)`; no disk access. Warm-up: one untimed call. `GOMAXPROCS=1`, count 10.
