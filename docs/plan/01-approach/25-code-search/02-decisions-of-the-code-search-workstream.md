#### Decisions of the code-search workstream

1. Engine: `github.com/google/codesearch` v1.2.0 names the candidate files. Rival: `github.com/sourcegraph/zoekt`. The owner named the two libraries on 2026-11-12, and the verdict on the engine in the design part of this plan gives the reasons against zoekt. The proxy lists v1.3.0-rc.1, a pre-release (https://proxy.golang.org/github.com/google/codesearch/@v/list), so the pin is v1.2.0, the newest tagged release. It was released 2020-03-29T22:17:33Z (https://proxy.golang.org/github.com/google/codesearch/@v/v1.2.0.info). Its module declares `go 1.13` and no requirements (`github.com/google/codesearch@v1.2.0/go.mod`). Its licence is BSD-3-Clause (`github.com/google/codesearch@v1.2.0/LICENSE`). Standard `regexp` stays the matcher, because the library only names candidate files.
   2. The index is advice. It lets the engine skip a file that its trigram query cannot match, and nothing more. Rival: trust the index for the answer. A stale or damaged index would then hide matches.
3. Covered rule. A file is covered when its record is indexed, its size, modification time and change time equal the record, both times are more than `racyWindow` older than the build start, and the clock reading is at least the build start. Git's racy-entry rule (https://git-scm.com/docs/racy-git) treats an entry whose times are as new as the index file as racily clean. This workstream uses a fixed two-second window. Rivals: size and modification time only, which a tool can defeat by restoring a modification time; hashing each file on each call, which reads every byte on every call; a filesystem watcher, which needs a process that always runs.
4. The index is opened only in the search child, which runs in the sandbox. Rival: open it in the host. The library calls `log.Fatal` on a corrupt index (`github.com/google/codesearch@v1.2.0/index/read.go:100`, and the function `corrupt` at `index/read.go:410-411`). A fatal exit in the host would end the agent.
5. Index failure is exit status 1 of the search child, and no other path of the child returns 1. `log.Fatal` exits with status 1 (https://pkg.go.dev/log#Fatal). A panic on the index path is recovered into `errIndex`, which also returns 1. Rival: a new status code. The library already exits with 1, so a new code would name a case that the library never sends.
6. Retry. When the search child exits with status 1 and the call used a generation, the parent removes `CURRENT` only if it still names the failed generation. It then runs the same call once without an index, under a new process id. Rival: reuse the call id. `docs/spec/recovery.md` says that `runner.Start` with the same call id MUST be a no-op, so a repeated start would return the old exit record.
7. Parent inputs. The parent appends the index root, the generation name, its own clock reading and the racy window to the search child's argument list, after the JSON. Rival: fields in the JSON arguments. The model writes those arguments, and `parseArgs` rejects unknown keys (`internal/tool/search/json.go:122`). Rival: environment variables, which need a second mechanism for the tests to check.
8. The product home comes from `tool.Env.Home`. The agent sets `Home` from `config.Config.Home` (`internal/agent/tools.go:390`), and `defaultConfig` sets that from `Product.Home()` (`internal/config/config.go:253`). `productHome` rejects a home that is not absolute (`internal/config/config.go:55-58`). Rival: `search.New(product)`. That changes the constructor in `internal/app/app.go`, the `investigative` map in `internal/agent/advisor/runtime.go:41`, and every test that builds the tool, and it adds a field that `tool.Env` already has. Rival: the user cache directory. `resolveRoots` adds the cache to every sandboxed child's writable roots (`internal/runner/sandbox_linux.go:73`), so a model command could rewrite a cached index. An empty or relative `Home` turns the index off.
9. The build child gets one extra writable root, its new generation directory. `resolveRoots` appends the roots that a `ProcessSpec` names (`internal/runner/sandbox_linux.go:72-73`, applied at `sandbox_linux.go:57`), and the darwin profile writes the same roots through `sandboxProfile` (`internal/runner/sandbox_darwin.go`). Reads are not restricted. Linux grants read-only access to `/` (`sandbox_linux.go:57`), and the darwin profile starts with `(allow default)`. The search child reads the index under the home. Model commands receive the workspace, the temp directory, the user cache and the configured roots. They never receive the generation directory.
10. Sandbox off, no Landlock, or no change time: the index does not apply. `Local.spawn` treats an empty mode as workspace write (`internal/runner/local.go:91`). On a host where the sandbox is off, a model command can write any file the user can write, so an index there could be planted. Without Landlock, `configureSandbox` applies no roots (`internal/runner/sandbox_linux.go:23-24`). In both cases the search reads every file and starts no build.
11. Containment. The index root must lie outside each of these directories: the workspace, `os.TempDir()`, `os.UserCacheDir()` when it succeeds, and each entry of `env.Sandbox.WritableRoots`. The host fills the writable roots from the working directory, the temp directory, the user cache and `sandbox_writable_roots` (`internal/agent/tools.go:388`). Each existing directory and the home are resolved with `filepath.EvalSymlinks` before the test, and the test is `escapesRoot`. Rival: keep the index in the workspace, where every model command could write it.
12. The build runs in a hidden child, `__search-index`, which the parent starts through `env.Runner` with the search call's sandbox mode. Rival: build in the host. The build reads the workspace, and an index over 4 GiB makes the library call `log.Fatalf` (`index/write.go:523`), which would end the host.
13. Trigger and count. A grep call starts one build when it counts at least `indexRebuildBytes` of bytes. A counted byte belongs to an uncovered file, except a file that the last build recorded as not indexed while its size and times still match that record. Such a file never enters the index, so counting it would start a build in every new process. The owner's measurement puts 1,781 files in that group (decision 26). Rival: count every uncovered byte, which starts a build in every new process for such a workspace. Rival: a cumulative counter in a state file, which needs persisted state and a reset rule that the owner did not ask for.
14. One build start per workspace per process. A `sync.Map` records the start with `LoadOrStore`. A failed build stays recorded for that process. A new process may build again. Rival: a file lock across processes, which adds platform code.
15. Two processes may build the same workspace. Each writes its own generation directory. The later rename of `CURRENT` wins, and the publisher removes the other generation directories. A build that another process is still writing can then fail, and its failure is logged. A search that finds `CURRENT` naming a missing directory treats it as no index (`currentGeneration`).
16. Build cap. A build records each eligible file while the total stays within `maxBuildBytes`, which is 1 GiB of file bytes. A file past the cap gets a record with `Indexed` false. The search reads it on each call and does not count it (decision 13). Rival: no record for a file past the cap. Such a file would count on every call, and each new process would start a build. Rival: no cap. The library allocates a 64 MiB posting buffer and a 64 MiB sparse set (`index/write.go:58`, `index/write.go:63`), and the cap bounds build time and index size.
17. Commit point. The builder syncs the trigram file, writes the manifest and syncs the generation directory before it exits with status 0. The parent publishes `CURRENT` only after exit status 0. The manifest records the trigram size, and the search child trusts a generation only when that size matches. Rival: a checksum on each call. It reads the whole index on every call, so it is ruled out.
18. Manifest format. A binary layout with explicit big-endian appends through `encoding/binary`. Rival: JSON through `jsontext`, which would parse a manifest on each indexed call. Rival: `encoding/gob`, which uses reflection, and `docs/decisions/dependencies.md` forbids reflection in wire codecs. The magic line names the library version, so an index from another codesearch version is rejected.
19. Lookup. `sort.Search` over paths in byte order. The builder adds records in walk order, and `walkScope` sorts entries by display path (`internal/tool/search/engine.go`, function `walkScope`).
20. Records. The builder writes a record for each regular file of at most 16 MiB that `searchableInfo` accepts and that has a change time. The library leaves a file out when it has a line over 2000 bytes (`index/write.go:94-96` for `maxLineLen`, and `index/write.go:164-168`), when it has more than 20000 distinct trigrams (`index/write.go:174-176`, `maxTextTrigrams`), or when it is over 1 GiB (`maxFileLen`, `index/write.go:94`). Such a file keeps a record with `Indexed` false, and the search reads it on each call. A file that `searchableText` rejects, because it holds a NUL byte in its first 8192 bytes or it is not valid UTF-8, also keeps a record with `Indexed` false. A symbolic link never enters the walk (`walker.excluded` in `engine.go`). Rival: index by modification time only, which a restored modification time would hide.
21. Platforms without change times, Windows included. `ctime_other.go`, under the build constraint `!linux && !darwin`, sets `ctimeSupported` to `false`. Consequence: no file is covered, the engine never skips a file, and the build trigger stays off. The owner's ruling asks for this rule. The Windows file information in the Go `syscall` package has no change-time field (`/usr/lib/go/src/syscall/types_windows.go`).
22. Query. `syntax.Parse` with `syntax.Perl`, then `index.RegexpQuery` on the parsed tree (`index/regexp.go:333`). `RegexpQuery` analyses the tree itself (`index/regexp.go:334-336`), so the caller does not simplify the tree first. A query of `QAll` makes every eligible file a candidate.
23. Planning counts. `planReads` stats every file that the walk returns, with or without an index. Without an index every read is counted, so decision 13 can fire.
24. The count travels only in the child's JSON as the member `unindexed`. `makeResult` does not write it, so the model never sees it.
25. Library messages. A fatal message from the library goes to the child's standard error. The shim joins standard error into the child's output (`internal/runner/shim.go:104-105`). On exit status 1 the parent logs that output at warn level with `slog.Default()`. The retry replaces the result, so the model never receives the message. The search child and the builder write nothing to standard error when they succeed.
26. Measured floor. These are the owner's observations of 2026-11-12 on one linux/amd64 host under heavy load, from a throwaway program. They are observations, not benchmarks. The library indexed this workspace of 43,277 eligible files and 260,677,421 bytes into an index of 25,137,933 bytes (9.6 percent) in 3.5 s. It left 1,781 files out, because of long lines or too many trigrams. For the literal `DefaultUses` the filter leaves 1,783 files to read: the 1,781 files that are left out, and the 2 files with a match. For `(?i)todo` it leaves 2,377 files. For a two-letter pattern the query is all, and every file is read. No pattern tried had a file with a match that the filter would skip. The patterns included `(?i)` against the Kelvin sign U+212A and the long s U+017F, a 2,500-byte line, and CRLF line ends. Consequence: the files that the library leaves out are read on every call, so they set the floor of every indexed grep. `BenchmarkGrepRareLiteral` and `BenchmarkBuildIndex` report that count as `rejected_files`. The property test of step 4 covers the same classes of input, so the claim is tested and not only observed.
27. Threshold and benchmarks. Benchmarks make no speed claim, and each hypothesis is labelled `[unmeasured]`. The baseline benchmarks land first (step 1), and the index benchmarks land with the index steps. The sweep of step 4 sets the value that step 6 gives `indexRebuildBytes` by one fixed rule: the smallest uncovered size whose indexed p95 is below its scan p95, or `1 << 32` when no size qualifies. The index lands whatever the numbers are.
28. Test seams. The racy window and the clock are fields of `freshness`, which the tests pass in. The threshold is a package variable that a test lowers and restores with `t.Cleanup`. Rival: `time.Sleep` for two seconds, which the repository forbids in tests. Rival: a constant, which no test could reach with a 32 MiB fixture on every run.
29. Clock check. The search child trusts nothing when its parent's clock reading is earlier than the build start. Rival: no check. A backward clock step could make a file changed after the build look older than the build.
30. Byte identity. The test compares the indexed run with the run without an index. The run without an index is the current engine, and its expectations are hand-written in `search_test.go`. Those tests keep their bodies. Rival: a saved output, which proves nothing.
31. Restore. Deleting the directory `<home>/search` restores today's behaviour, because a search without an index reads every file. The cache is bounded per workspace: one current generation and at most one generation being built. No global size cap is added.
32. Dependency row and notice. The Version pins workstream writes the codesearch row into `docs/decisions/dependencies.md` (cross-phase decision 25). Step 3 replaces that row's Decision cell. The BSD-3-Clause licence requires that binary redistributions reproduce the copyright notice, the conditions and the disclaimer, which the binary-redistribution condition of `LICENSE` states. Step 3 therefore adds the codesearch section to `THIRD_PARTY_NOTICES.md`, and creates the file when it is absent. Rival: a notice generated from `go.mod`. The plan writes its notices by hand, one section for each module.
33. Scope. The index covers the workspace. A grep scope inside the workspace uses the same index, because the lookup uses the display path. `resolveScope` refuses a path outside the workspace (`internal/tool/search/engine.go`, function `resolveScope`), so no scope needs its own index. Rival: one index for each scope, which multiplies builds.
34. Recovery. A build is not a tool call and writes no journal event. A grep call is read class, so recovery runs it again (`docs/spec/recovery.md`, the row for `tool.started` of class `read`), and a repeated grep only reads files. A crash during a build leaves one generation directory, and the next publish removes it. Step 6 adds two sentences to `docs/spec/recovery.md`.
35. The model-visible schema and the output do not change. This workstream does not change the `search` tool description.
36. Shared code. `walkScope`, `resolveScope`, `searchableInfo` and `readSearchable` in `engine.go` are the only walk and eligibility code. The builder, `planReads`, `scanFile` and the later `search.Select` of the Code rewrite workstream call them. No second walk or eligibility rule is written.
37. The index applies only to the `grep` branch of `execute`. The Code symbols workstream passes an empty directory for its own modes, so those modes never read an index.
38. Owner decisions carried forward. The grep index uses `github.com/google/codesearch`. No step adds ast-grep. The Code symbols and Code rewrite workstreams own their modes and their spec rows. The owner fixed codesearch, so this workstream adds no dependency-order rule that would reject it. The age of codesearch (last tag 2020) is in the design record of this plan.
39. Lint. Each new function stays at cyclomatic complexity nine or less (`.golangci.yml:30`). The functions `buildIndex`, `planReads` and `runGrep` are split into helpers. Cognitive complexity stays at 14 or less (`.golangci.yml:32`).
40. Core rule. The codesearch import stays in `internal/tool/search`. Core packages import no interface package and no battery (`.golangci.yml:99-132`, and `**/internal/tool/**` at `.golangci.yml:105`). codesearch is a library, not a battery, so no depguard entry changes.
41. No step adds a prose comment to Go code. The comment gate of Verification item 11 runs in `just verify`.
