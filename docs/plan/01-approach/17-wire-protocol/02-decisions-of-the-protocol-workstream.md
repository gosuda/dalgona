#### Decisions of the protocol workstream

1. Diffs are real unified diffs computed from journaled pre and post images by `textdiff.Unified` in `internal/textdiff`, which is built on `github.com/aymanbagabas/go-udiff` v0.4.1 and created by the edit-review workstream, Step 1. Rejected: the per-file patch section (`patchSection`, `internal/rpc/serve_items.go:205-220`), because the default `anchor` style and the `replace` style carry no diff text, so the section is the raw tool arguments.
2. Times come from the journal: `turn.started`, `turn.completed`, `tool.started` and `tool.completed` gain an optional RFC 3339 timestamp stamped once in `actor.appendCtx`. Rejected: emission time in rpc, because snapshots and catch-up replays would show wrong or missing durations.
3. The context window is journaled on `assistant.message.context_window`. Rejected: a provider lookup inside the rpc tracker, because it would call the network from the watcher goroutine and differ on replay.
4. The sandbox choice uses the Codex server request `item/tool/requestUserInput` with one two-option question, preceded by a Codex `warning`. Rejected: a new `dalgona/` request, because both clients already need the question panel for the ask tool (product decision 8).
5. The choice is per thread, asked at the first `exec` call that would run sandboxed, and journaled as `sandbox.chosen`. Rejected: one choice per host at start, because a thread that never runs a command should not ask and recovery must see the choice in the thread journal.
6. `Accept` sends every exec call of the thread to the human approval path (`worker.human`, `internal/agent/gate.go:251`), and session grants (`acceptForSession`) do not apply in that thread (cross-phase decision 4). Rejected: honouring grants, because a grant from earlier in the thread would skip the choice the user has just made.
7. Keyword matches come from a server method for the composer and from a `keywords` member on the `userMessage` item for the sent prompt. Before a thread has resolved its tools, requirement checks are skipped (the composer view is a preview; the item is authoritative). Rejected: resolving tools to answer a keystroke, because tool resolution can ask for workspace trust.
8. Live settings move into `agent.Host` (`Host.Config`, `Host.WriteSettings`). Rejected: extending the rpc `settingOverrides` map (`internal/rpc/serve_thread.go:207-250`), because the agent never sees it, so a `/settings` change such as `reasoning` would not reach the worker.
9. The interactive settings, their defaults and their options live in one table `config.InteractiveSettings`. Rejected: option lists in each client, because they would drift from validation.
10. An API key is verified by listing that provider's models before it is kept; on failure the previous credential is restored. Rejected: storing blindly, because the panel must validate on submit (product decision 7).
11. `command/exec` runs through `agent.Host.Exec` on a Local runner under the configured sandbox; stdout and stderr arrive merged as `stdout`; `tty`, `streamStdin` and `size` are rejected. Rejected: `os/exec` in rpc, because it would bypass the shim sandbox and the runner exit records.
12. `fs/*` takes absolute host paths with no workspace confinement. Rejected: confinement, because a client that may call `command/exec` already has the same reach, and a partial fence would mislead.
13. `fs/watch` polls once per second. Rejected: `github.com/fsnotify/fsnotify`, because no current client calls `fs/watch` and a new direct dependency is not worth one method.
14. `fuzzyFileSearch` reuses the gitignore-aware walker of `internal/tool/search` through a new exported `search.Files`, returns files only, at most 50. Rejected: a second walker in rpc, because ignore rules would diverge.
15. MCP status reaches rpc through `agent.HostConfig.MCPStatus`, filled by the dalgona battery. Rejected: a `ServeOptions` hook, because `dal` and the daemon build hosts in one place (`internal/app/app.go:88-94`) and rpc must not import `internal/mcp`.
16. Truncated output is read back through `dalgona/item/output/read`. Rejected: `fs/readFile` on the spill path, because exec spills can live in a remote box and the text must be masked.
17. `dalgona/` messages get draft-07 schemas under `internal/rpc/testdata/dalgona-schema/`, enforced by the wire test client. Rejected: documentation only, because the web validator needs a machine-readable contract.
18. `review/start` starts an ordinary turn on the given thread with a fixed review prompt; only `inline` delivery. Rejected: Codex review-mode items, because no client renders them.
19. Diff line counts ride as extension members `additions` and `deletions` on each change. Rejected: client-side counting, because both clients would duplicate the parser.
20. The tracker's keyword source is the method value `s.host.KeywordMatches`, called with the `threadID` the tracker already holds. Rejected: a closure built per thread in `s.newTracker`, because it only rebinds a value the tracker has.
21. Preset roles are read in `modelList` from `model.PresetFor`. Rejected: `agent.PresetRoles`, because it re-wraps one call and adds a layer between rpc and model.
22. `NewHost` fills `HostConfig.SandboxCause` with `runner.UnavailableCause` when it is nil, and callers read the field. Rejected: a `Host.sandboxCause()` wrapper, because it adds a name over the same field.
23. `textdiff.Limit` (1 MiB) alone decides when a side is not diffed, in rpc and in the approval. Rejected: a second `diffLimit` constant in rpc, because two copies could disagree.

Every step ends with `just verify` (`justfile:121`), one concern per commit, and no prose comment in Go, Svelte, Python or hand-written TypeScript, doc comments included; only `//go:build`, `//go:embed`, `//go:generate` and `//nolint:<linters> // <reason>` stay.
