#### Outcome of the protocol workstream

Both clients can show turn and command durations, a context gauge after a resume, real unified diffs with line counts (also inside an edit approval), and the full text of a truncated output, all from server data. The server reports keyword matches with byte ranges and their effect, so `internal/tui/keywords.go` can drop its copy of the matcher. `/login` stores and verifies an API key and always ends in `account/login/completed`; `/settings` and `/model` read and write the seven interactive settings and a model list with presets and context windows. When the harness sandbox is asked for but missing, the user sees a warning and chooses `Accept` or `Dangerously accept`; without a client the command is declined. The Codex methods `review/start`, `mcpServerStatus/list`, `config/batchWrite`, `command/exec`, `fs/*` and `fuzzyFileSearch` answer instead of `-32601`, and every `dalgona/` message has a schema that both clients can validate against.
