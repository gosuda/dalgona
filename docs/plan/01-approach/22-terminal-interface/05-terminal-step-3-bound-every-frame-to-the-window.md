The old `renderView` (`model.go:644-662`) is deleted. It put the live items and the notice above the composer.
- Height. Let `c` be the editor rows, `p` the panel rows and `H` the window height. `c = max(1, min(wrapped editor lines, composerMaxRows, H-3))` with `const composerMaxRows = 6`, so `c` is at least 1. While a panel is open, `c` is 1: the composer shows only the input line (cross-phase decision 53). `p = panelRows(kind, H)` when a panel is open, else 0. `func panelRows(kind panelKind, windowHeight int) int` returns `max(0, min(rows, windowHeight-4))`, where `rows` is the fixed height of the kind in the table of Step 21 (cross-phase decision 53). The queue panel is a `panelList`. The live row and the status band count two rows. The height before the fit is `c + p + 2`. The fit below keeps it at most `H - 1` for a window of 2 rows or more. For a window of fewer than 2 rows, `dockLines` returns nil (print rule 4).
- Fit. While the height is above `H - 1`, drop in this order and stop as soon as it fits: the editor rows down to 1, the status band (not drawn), and the live row (not drawn). The panel is not cut by the fit: `panelRows` caps it at the window height minus 4, and `framePanel` keeps its title first and its action rows last. The input line is never cut.
- Bounds (I6): the number of lines is at most `H - 1`, which is `len(lines) <= screen.height - 1`, for a window of at least 2 rows. The renderer drops rows only above the height (`bubbletea/v2@v2.1.1/cursed_renderer.go:353-357`). Every row is at most `width - 1` cells by `cells`. Each row is built from fixed fields, `m.screen.fit` or `m.screen.wrap`, so no row wraps.
- A resize changes the height in two cases only: the bound forces it, or the editor wraps into more rows at the new width.
- `panels.go`: add `type panelKind int` with the kinds `panelPopup`, `panelList`, `panelConfirm`, `panelApproval`, `panelAsk`, `panelSettings`, `panelLogin` and `panelHelp` (heights in the table of Step 21), and `type panelView struct{ kind, id string; layout panelKind; decision bool; title string; body []string; actions []string; scroll, cursor int }` and `func framePanel(p panelView, width, rows int) []string`. `kind` and `id` are empty for a plain panel. `decision` is true for approval, ask and confirm panels, and their first action takes the one fill in the thread hue (Design record, The point and the thread hue). `cursor` is the selected body line, or -1 for none. The frame is the Open rail of the Design record, Terminal panels: the title line has the prefix `┌ `, body lines the prefix `│ `, the line at `cursor` the prefix `┃ ` in `text` with bold text (no tone fill, since the terminal paints no background), and the action block the prefix `└─ ` on its first line. Prefix cells count toward `width`, which the caller passes as `terminalWidth(m.screen.width)`. The title is always line 1, cut with `m.screen.fit(s, width)`. The action lines are always last. They use the one-line join or one label per line, as `approvalChoices` does (`model.go:714-720`). The body window fills the rest. When the body is cut, the last body line is `↓ N more lines · ↑↓ scroll`.
