#### Terminal step 15. Review overlay on `ctrl+o`
Anchor: Italo Calvino

- `review.go`: `type entry struct{ key, title, text string }`; entries are recorded by `commit` with the full untruncated body (the last 1000 per thread, oldest dropped). `type reviewState struct{ index int; view viewport.Model; live *entry }`. `view` is `charm.land/bubbles/v2/viewport`, built with `viewport.New(viewport.WithWidth(w), viewport.WithHeight(h))` (`bubbles/v2@v2.2.1/viewport/viewport.go:27-43`). Its body is `view.SetContentLines(lines)` with the lines already wrapped (`bubbles/v2@v2.2.1/viewport/viewport.go:233`). Set `view.KeyMap = viewport.KeyMap{Up: key.NewBinding(key.WithKeys("up", "k")), Down: key.NewBinding(key.WithKeys("down", "j")), PageUp: key.NewBinding(key.WithKeys("pgup")), PageDown: key.NewBinding(key.WithKeys("pgdown"))}` (`viewport/keymap.go:20-58`, `key/key.go:50-112`). A zero `key.Binding` is disabled (`key/key.go:50-112`; `Enabled` needs a non-nil key list), so the defaults `space`, `f`, `b`, `u`, `d`, `h` and `l` stay off.
- The review opens only on `ctrl+o`. It closes only on a key: `esc`, `q` or `ctrl+o`. A quit or suspend key (`ctrl+c`, `ctrl+z`) closes it first: `closeReview` runs before `quit()` or `suspend()` (Step 13 and Step 37), as Bubble Tea practice rule 17 requires. A window size message resizes the viewport and does not close the review. No timer, stream or notification opens or closes it. `ctrl+o` opens on the newest entry. While an item streams, it opens on a snapshot of that item. From the approval card it opens the full command and diff. Keys: `up`/`k`, `down`/`j`, `pgup` and `pgdown` go to `view.Update`. `home`/`g` call `view.GotoTop()` and `end`/`G` call `view.GotoBottom()` (`bubbles/v2@v2.2.1/viewport/viewport.go:581-595`), because the viewport KeyMap has no home or end key (`viewport/keymap.go:20-58`). `[` previous entry, `]` next entry.
- Rows that finish while the review is open wait in `m.out.pending`, because `drain` prints nothing while the review is open (Step 3). `func (m *model) closeReview()` (new, `review.go`) sets `m.review` to nil and does nothing else. The view leaves the alternate screen, the frame settles, and `drain` prints the waiting rows in order (print rules 2 and 3). A print before the renderer leaves the alternate screen would be lost, because `insertAbove` has no alternate-screen check (`bubbletea/v2@v2.1.1/cursed_renderer.go:772-826`). Closing repaints nothing else: it sends no `tea.ClearScreen` and writes no clear sequence. The dock is drawn again in its old place after the alternate screen closes. `TestReviewHoldsRowsUntilClose` checks it.
- `View`: while the review is open, set `AltScreen = true` (`bubbletea/v2@v2.1.1/tea.go:175`). Otherwise `AltScreen` stays false. The mouse mode is set in Step 35 only.
- Content: header `Review · <title> · i/n`, body window, footer `↑↓ scroll · [ ] items · Esc close`. The wheel is the viewport's: `tea.MouseWheelMsg` with `MouseWheelUp` or `MouseWheelDown` moves 3 lines by default (`bubbles/v2@v2.2.1/viewport/viewport.go:66-69, 150-151, 696-721`; `setInitialValues` sets `MouseWheelEnabled` and a delta of 3), so route every `tea.MouseWheelMsg` to `view.Update`.
