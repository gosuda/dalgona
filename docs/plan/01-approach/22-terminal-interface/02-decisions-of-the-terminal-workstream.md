#### Decisions of the terminal workstream

Each entry gives the choice, the rejected rival and one reason.

1. One Go package `internal/tui` split into files by concern. Rejected: sub-packages per concern. Sub-packages would force exported surfaces between pieces that share one Bubble Tea state, which adds busy abstraction for no current requirement.
2. One state struct `model` with grouped sub-structs (see Structure). Rejected: a model per component with its own `Update`. Message routing then needs a second dispatch layer, and the panel stack needs global state anyway.
3. The internal state strings `idle`, `running`, `awaiting approval`, `interrupted`, `failed`, `disconnected` (`internal/tui/model.go:19-26`) and `awaiting input` (the ask workstream, Step 7, constant `stateAwaitingInput`) stay as the `Status.State` contract. The words `Ready`, `Working`, `Waiting`, `Done`, `Stopped`, `Failed` and `Offline` are display only (cross-phase decision 50). Rejected: renaming the constants. `cmd/dalgona/client.go:161-169` maps `running` and `awaiting approval` to herdr states.
4. Validate canonical text at ingress and retain it unchanged. Build one safe display projection with source mappings, including state for split terminal escape sequences. Cache that projection by source revision. Never sanitize a path, option value, draft, or protocol identity into a different authoritative value. [Input text](../../../dal/spec/input-text.md) and Terminal step 2 define this boundary.
5. The theme layer reads `NO_COLOR` itself (any non-empty value, as no-color.org defines it) and downsamples every committed row through `colorprofile.Writer`. Rejected: relying on Bubble Tea's renderer. `tea.Println` goes through `insertAbove`, which writes the string raw (`bubbletea/v2@v2.1.1/cursed_renderer.go:772-826`). `colorprofile.Detect` also parses `NO_COLOR` with `strconv.ParseBool` (`colorprofile@v0.4.3/env.go:115-117`), so `NO_COLOR=yes` would keep colour.
6. The terminal background is never painted. The point (Design record, The point and the thread hue) is the only fill: the first action of an open decision, else the live tag, and both take the thread hue. The prompt marks take the hue as text colour. Diff signs, keyword marks, links and warnings take text roles. Selection uses bold and a rail, never a fill. Rejected: painting the Radix slate ground in the terminal. A painted ground fights the user's terminal theme and breaks selection. Ground roles stay for the web.
7. Light or dark comes from `tea.RequestBackgroundColor` and `tea.BackgroundColorMsg.IsDark()` (`bubbletea/v2@v2.1.1/color.go:14-16, 78-80`). Until the reply arrives the theme is `night`, or `soft-night` when the setting is `auto-soft`. Rejected: `lipgloss.HasDarkBackground` (`lipgloss/v2@v2.0.6/query.go:86`). It reads the tty directly and blocks, and it does not work through the injected `Options.Input`.
8. Motion is one tick chain that runs only while the state is `running`, `awaiting approval` or `awaiting input`, or during a rate-limit wait. It ticks every 500 ms, and once a second with motion off. The tick drives the breathing dot, the elapsed counter and the rate-limit countdown. Rejected: a 100 ms tick, the current shimmer (`model.go:616-635`). The defect is an unbounded fast timer, and whole-second elapsed text does not need a faster tick.
9. The keyword glow becomes a static mark: bold plus underline, with the `accent-text` role when colour is on, and no tick. Rejected: keeping the 14-stop gradient. The design forbids gradients, and the gradient signals by colour only.
10. A truncated approval card body scrolls in place with up and down, and `ctrl+o` opens the full text in review. Rejected: refusing `y` until the full command was viewed. That adds a gate on every long command, and the defect (Bubble Tea dropping the title and the command) is fixed by bounding.
11. Follow-ups move with a thread switch and are held, with a notice. Rejected: a confirm dialog on every switch, because it is friction for a rare case. Rejected: discarding, because that is the defect.
12. A prompt starting with `/` is sent when it starts with `//` (one slash removed) or when its first token contains a second `/` (a path). Unknown `/word` stays in the editor with a notice. Rejected: sending every unknown command as a prompt. A typo such as `/modle` would reach the model.
13. Thread-changing commands (`/new`, `/resume`, `/fork`, `/compact`, `/tree`, `/revert`) are refused while a turn is working or waiting. Rejected: guarding only three of these commands. `/resume`, `/tree` and `/revert` change the followed thread or branch in the same way.
14. Esc interrupt guard: the first Esc while working shows the hint `Esc again to interrupt` for 2000 ms, and the second Esc inside that window interrupts. Ctrl+C uses the same 2000 ms window to quit. The hint uses the live row (decision 40 of this workstream). Rejected: making Ctrl+C the cancel key (the grok-build model). The spec and README teach Esc for interrupt.
15. Durations use one form, live and committed: `<n> ms` under one second, `<s>s` under one minute, `<m>m <ss>s` under one hour, and `<h>h <mm>m` from one hour (cross-phase decision 33). A ticking duration sits right-aligned in a 7-cell field. Token counts are not shown: the status band shows a context percent (Design record, Status band), and no other surface needs a count. Rejected: one-decimal live seconds, which needs a 100 ms tick, and a split where committed rows used `{s.s}s` while the live row used whole seconds, so one duration showed two forms.
16. History is the user messages of the current thread (from `thread/read` and from `item/completed`), plus the prompts sent this session. It is capped at 200, drops consecutive duplicates, and never stores `/login` lines. Rejected: an on-disk history file. It needs a new path option through `internal/app` and secret filtering on disk.
17. Paste chip threshold: 10 or more lines. Hard cap: 1 MiB per paste. Rejected: grok-build's 4 lines, which hides ordinary short snippets the user wants to see and edit.
18. `!` shell mode runs `command/exec` and commits a row. Its output becomes a context chip in the editor that the next prompt carries. Rejected: injecting the output into the thread silently (Codex `thread/shellCommand`). The chip leaves the user in control of what the model sees.
19. Image paste accepts a pasted path to a `.png`, `.jpg`, `.jpeg` or `.gif` file of at most 5 MiB, at most 10 images per prompt. `ctrl+v` reads the OS clipboard image through `wl-paste`, `xclip`, `pngpaste` or PowerShell (cross-phase decision 17).
20. Notifications go out only while the terminal is blurred: OSC 99 for kitty, OSC 9 for iTerm.app, WezTerm and ghostty, BEL elsewhere and inside tmux. One setting, `notifications` (boolean, default `true`), turns them off (cross-phase decision 49). Rejected: one setting per event, which adds options with no current need. BEL while blurred is mild.
21. Verbosity `medium` caps diffs at 60 lines per file and command output at the last 10 lines. `high` shows everything. Rejected: uncapped diffs at medium, which floods scrollback on large edits. Review always has the full text.
22. Mouse reporting is on only while the review overlay or a list panel is open. Rejected: mouse always on, which takes native selection and scrollback away from the user.
23. Review keeps the last 1000 entries per thread. Rejected: unbounded memory for very long threads.
24. Terminal icons: `icons` `auto` starts as `unicode`. With `KITTY_WINDOW_ID` set, one capability query is sent at start, and a reply that names a Nerd Font switches to `nerd` (Design record, Icons). Rejected: probing every terminal with a timeout, which needs a second clock and misreads terminals that never answer. The reply `Content` is `name=value` pairs joined by `;` (`parseTermcap` in `ultraviolet@v0.0.0-20261008173134-6b8d4baf91b4/decoder.go:1790-1832`, which hex-decodes names and values); the kitty reply is an external check, with a Unicode fallback when no reply comes (Step 12).
25. One Esc stops a rate-limit wait (cross-phase decision 41). Rejected: the double Esc of decision 14 of this workstream. The wait holds no output to lose, and the live line says `esc stops`.
26. The status band shows the eight items of Design record, Status band. The state word leaves the band, because the live row and the window title already show it. Rejected: keeping the state word in the band, which repeats the live row.
27. The rate-limit countdown updates every second even when `DAL_NO_MOTION` is set. Rejected: following the motion switch. A stale countdown is wrong, not decorative.
28. The point (Design record, The point and the thread hue): while an approval, ask or confirm panel is open, its first action takes the one fill, in the thread hue, and the live tag is plain `warning-text` text. Send has no fill in the terminal: the prompt mark carries the hue. Rejected: two fills in one view, which Design record, The point and the thread hue forbids.
29. Two regions: history and the dock. History is every row above the dock. The dock is the last rows and the only part that changes. A finished item is written to history once and is never written again: not on resize, theme or verbosity change, thread load, or exit. Rejected: rewriting history after a resize, a theme change or a verbosity change. A row that is taken back has no identity, and the reader loses the place (design, "Two regions").
30. Never clear. While inline, the client never erases the display or the scrollback, never resets the terminal, and never moves the cursor home. It returns no `tea.ClearScreen`. Rejected: clearing the screen on resize or thread switch. A clear removes the identity of every row at once and cannot bring the scrollback back.
31. The dock keeps its height. Its height is the editor rows, plus the rows of an open panel, plus two for the live row and the status band. A key press, a paste, or the open or close of a panel may change it. A window resize may change it too (cross-phase decision 52; Step 3 gives the fit order). Time, streamed text, progress, the start and end of a turn, notices and hints never change it. Rejected: a dock that grows with live items, notices, plan lines and the selector, as `renderView` does today (`model.go:644-662`). Each height change repaints the dock and moves the rows the reader is following.
32. Fixed fields. A value that changes with time or with a count keeps its cells: the elapsed time, the calls count, the plan step, the queue count and the live dot. Free text sits to the right of these fields and is cut with `...`. Rejected: fields that widen with their value, and a status row that wraps (`statusRow`, `model.go:672-681`). A field that moves makes the reader lose its place.
33. A stream is written in final blocks. Answer text is cut at the boundaries of the block splitter (Step 17), and each final block is printed once. The unfinished rest shows as one tail row in the live row. Rejected: the whole stream in the dock, which is today's uncapped live item (`model.go:471-487`, `model.go:684-693`), and partial text in history. Partial text may still change, and a dock that holds the whole stream cannot keep its height.
34. The composer is the first part of the dock, and the live row is below it. The dock order is the editor, the open panel, the live row, the status band. Rejected: the live row above the composer, which `renderView` uses today (`model.go:646-660`). After a narrowing, a row above the cursor's row can leave a stale copy on screen. The cursor sits on a composer row, so the rows below it are the rest of the composer and the rest of the dock, and the rows above it are the user's typed text.
35. One input line. Every text the user types goes to the one cursor, in the editor. A panel shows choices and holds no text field. Rejected: text fields inside panels, such as ask answers and list filters. The terminal has one cursor, so a second text field needs a second place for the cursor.
36. The cursor is always set. `View.Cursor` is non-nil while the client is inline, and the terminal draws the cursor. The client draws no cursor glyph. Rejected: the drawn glyph `▏` (`composer.go:56-61`) with `View.Cursor` unset. The renderer then leaves the cursor on the last written cell, and the resize rule needs the cursor's row.
37. One cell short. Every dock row and every printed row is at most `width - 1` cells, measured by `screen.cells`. Rejected: the full width (`wrapTerminal` at `m.width`, `render.go:215-217`). A row that fills the last column can wrap in the terminal, and a wrapped row changes the height of the dock.
38. One print path with a height bound. `drain` prints one chunk at a time, of at most the window height minus the dock rows, only on a settled frame (print rule 2). The dock is at most the window height minus one, so every chunk has room for one row (print rule 4). Rejected: one `tea.Println` for an item of any length (`model.go:448-449`), and a `tea.Sequence` of chunks that is computed once, because a key press between two chunks can grow the dock. When the printed rows plus the frame rows exceed the window rows, `insertAbove` scrolls frame rows into scrollback and writes at the wrong row (`bubbletea/v2@v2.1.1/cursed_renderer.go:772-826`).
39. The last view is one blank row. While leaving, `View` returns one line that holds one space, and the program status is idle. Rejected: an empty last view on quit, which the earlier Step 37 returned. The renderer erases from the last row of the last view, so an empty view erases the last history row (`cursed_renderer.go:201`).
40. The live row carries notices and hints. A notice or a hint shows in the live row and adds no row. A notice that does not fit the live row is also printed once as a history row with key `note:<n>`, so its full text stays in history. Rejected: a notice block above the dock (`renderView`, `model.go:655-657`) and a hint in the status band (earlier Step 13). Each extra row changes the height of the dock.
41. Progress is a field and a history row. A plan change writes one history row, and the live row shows the plan as a field. A subagent counts in the calls field, and its committed row lists its child sessions. Rejected: a plan panel and a subagent block that grow the dock (earlier Steps 18 and 3). A region that grows changes the dock height with no key press.
42. The queue is a field, and the queued texts show by key. The queue count is a fixed field in the status band and in the live row. The queued texts show in a panel that `alt+q` opens. Rejected: a queue region above the editor (earlier Step 32), which changes the dock height when a follow-up is added.
43. The welcome row keeps to the default foreground. It uses only the default foreground, bold and dim. Rejected: the accent colours of Design record, Status band (earlier Step 37). A written row keeps its colours, and the theme may not be known when the welcome row is written.
44. Caps. The editor shows at most `composerMaxRows` (6) rows. A panel has the fixed rows of its kind (`panelRows`). Rejected: a composer cap of `clamp(height/3, 3, 10)` (earlier Step 3), which changes with the window height, so a resize would change the dock with no key press. `composerMaxRows` is 6. Panel heights are fixed by kind (cross-phase decision 53).
45. The live row shows a state word when the state matters. While a turn runs, and when the state is `interrupted` (shown `Stopped`), `failed` (shown `Failed`) or `disconnected` (shown `Offline`), the live row shows the state word in its field (cross-phase decision 55). Idle shows the notice or the hint, or nothing. Rejected: a blank live row whenever no turn runs, which is the literal rule of the design. Those three states would then show in no row of the dock.
46. Final-block boundaries for answer text. A paragraph is final at a blank line. A heading and a rule are final at their line end. Each line of a fenced code block is final at its line end. A list, a table or a quote is final after a blank line when a line that does not belong to it follows. Rejected: a final block at every delta. A delta can end inside a word or inside a fence, and then a fence or a list would print as plain text.

The one state struct (in `state.go`):

```go
type model struct {
	conn    connInfo
	thread  threadInfo
	live    liveState
	input   inputState
	queue   []string
	panels  []panel
	review  *reviewState
	screen  screenState
	out     outState
	notice  string
	noticeN int
	hint    hintState
	leaving bool
	quitting bool
	suspending bool
}
```

No field is a region. The dock is built from these fields in `View` on every frame, and no field holds a line that grows with the content.

The fields that the block above lists, in its order:

- `conn` (`connInfo`): client caller, `opts Options`, `done <-chan struct{}`, `clock func() time.Time`, `product`, `version`, `platformFamily string`.
- `thread` (`threadInfo`): `id`, `title`, `state`, `seq`, `turnID`, `turnStartedAt time.Time`, `lastTurn time.Duration`, `completedTurns map[string]struct{}`, `modelName`, `effort`, `approvalMode`, `sandbox string`, `usage rpc.ThreadTokenUsage`.
- `live` (`liveState`): `items []liveItem`, where each `liveItem` has `split blockSplitter`; `deltas *deltaDecoder`; `plan []rpc.TurnPlanStep`; `planN int`; `group []row`.
- `input` (`inputState`): `editor editor`, `history history`, `popup *completion`, `mode inputMode`.
- `queue`: `[]string` of follow-ups.
- `panels`: `[]panel`, a stack; server cards (approval, ask) sort above user panels.
- `review`: `*reviewState`, the full-screen review of Step 15, nil when closed.
- `screen` (`screenState`): `width`, `height int`, `focused bool`, `theme theme`, `themeSetting string`, `color`, `motion bool`, `profile colorprofile.Profile`, `verbosity string`, `dark`, `hasDark`, `notifications bool`, `spin spinner.Model`, `ticking bool`, `env tea.EnvMsg`, `method ansi.Method`.
- `out` (`outState`): `printed map[string]struct{}`, `entries []entry`, `pending []string`, `printing bool`, `frozen tea.View`, `geometry frameGeometry` (the geometry that the last message stored, see the committed-row rule), `started bool`, `settling bool`, `settleN int`, `markdown map[mdKey]*glamour.TermRenderer`, `seq int`, `loads int`. The field `loads` counts the thread loads of this run: each `applyResumed` and `applyNewThread` result adds one before its commit.
- `frameGeometry` (Structure, `rows.go`): `rows int`, the line count of the content of `m.dockView()` (0 for the empty view), `width` and `height int` (the window size), and `altScreen bool`.
- `notice`: `string`, shown in the live row; `noticeError` marks an error notice (Step 2).
- `noticeN`: `int`, counts notices that were also printed as note rows.
- `hint` (`hintState`): `text string`, `id int`, `pending string`.
- `leaving`: `bool`, set when a quit or a suspend starts; `View` then returns one blank row.
- `quitting`: `bool`, set by `quit` with `leaving`; `finishQuit` returns `tea.Quit` only when it is true and either the window height is 0, or no print is in flight, the frame is settled and `m.out.pending` is empty.
- `suspending`: `bool`, set by `suspend` with `leaving`; `finishSuspend` returns `tea.Suspend` only when it is true and either the window height is 0, or `m.out.printing` is false and `m.out.pending` is empty, and it clears the field when it returns `tea.Suspend`.

Message types: `notificationMsg`, `serverRequestMsg`, `requestAnswer`, `resultMsg`, `disconnectedMsg` (exist at `model.go:85-114`). `spinner.TickMsg` (`bubbles/v2@v2.2.1/spinner/spinner.go:124-128`) replaces `shimmerMsg` (`model.go:110`). New: `printedMsg struct{}`, `settledMsg{n int}`, `hintExpiredMsg{id int}`, `searchResultMsg{seq int; files []fileHit; err error}`, `debounceMsg{seq int}`, `shellResultMsg{n int; command string; result rpc.CommandExecResponse; err error}`. The program also handles these Bubble Tea messages: `KeyPressMsg`, `PasteMsg`, `WindowSizeMsg`, `FocusMsg`, `BlurMsg`, `EnvMsg`, `BackgroundColorMsg`, `ColorProfileMsg`, `MouseWheelMsg`, `MouseClickMsg`.

Dock form: `View` returns the dock lines joined by a newline, with `AltScreen` false while inline. While `m.out.printing` is true, `View` returns `m.out.frozen` (print rule 3). Until the first row has printed, it returns the empty view, unless `m.leaving` is set (print rule 5). While `m.leaving` is set, `View` returns one line that holds one space (Step 37).

Committed-row rule: every write to scrollback goes through `commit`, defined in Step 3. It returns nothing and starts nothing. When `key` is already in `m.out.printed`, it does nothing. Otherwise it records the key and appends `lines` to the queue `m.out.pending`. `func (m *model) drain() tea.Cmd` is the one place that prints. It returns nil when a print is in flight (`m.out.printing`), when the frame is not settled (`m.out.settling`), when the review is open, when `pending` is empty, or when the bound `m.screen.height - len(m.dockLines())` is below 1. Otherwise `func (m *model) takeChunk() []string` moves rows from the head of `pending` into one chunk. It wraps each line with `m.screen.wrap` at `terminalWidth(m.screen.width)` and stops when the chunk holds as many rows as the bound. Rows of a wrapped line that do not fit go back to the head of `pending`. `func chunkText(rows []string) string` joins the rows with a newline and returns one space when the join is empty. `drain` stores `m.dockView()` in `m.out.frozen` (print rule 3), sets `m.out.printing`, passes `chunkText(rows)` through `m.screen.emit`, and returns `tea.Sequence(tea.Println(text), func() tea.Msg { return printedMsg{} })`. The runtime sends the messages of a sequence one at a time and in order (`bubbletea/v2@v2.1.1/tea.go:923-947`), so `printedMsg` arrives after the print has run (`tea.go:892-893`). `chunkText` returns one space for one empty row, because `insertAbove` returns at once for an empty string (`bubbletea/v2@v2.1.1/cursed_renderer.go:776-778`). `m.dockView()` is `View()` without its print branch, so it is the view that `View()` builds from the state when no print is in flight. `frameGeometry` is built from `m.dockView()`: `rows` is the line count of its content (0 for the empty view), `width` and `height` are `m.screen.width` and `m.screen.height`, and `altScreen` is its `AltScreen` value. `Update` runs the handler of each message first. A handler may call `commit`, and it starts no print. Then `Update` builds the `frameGeometry` of the fresh view and compares it with `m.out.geometry`, the value that the previous message stored. When they differ, it stores the new value, sets `m.out.settling`, increments `m.out.settleN`, and batches `tea.Tick(settleDelay, ...)`, which sends `settledMsg{n}`. Then it batches `m.drain()`, `m.finishQuit()` and `m.finishSuspend()`. So no handler prints on a frame that has not settled, and no command can be dropped, because `commit` returns none.

Print rules: the renderer's `insertAbove` scrolls by the printed rows and then moves up by the printed rows plus the height of the last frame it drew (`bubbletea/v2@v2.1.1/cursed_renderer.go:772-826`). So printed rows plus frame rows must not exceed the window rows. Otherwise frame rows scroll into scrollback and the text lands on the wrong row. `insertAbove` has no alternate-screen check, and the frame height and the screen mode change only at the renderer's next flush (`cursed_renderer.go:296-368`), 60 times a second (`bubbletea/v2@v2.1.1/renderer.go:13`). Five rules follow.

1. One printer. `commit` appends the rows to `m.out.pending` and returns nothing. `drain` is the only code that calls `tea.Println`, `Update` is its only caller, and one print is in flight at a time (`m.out.printing`).
2. Settled frame. A print starts only when the dock height, the window size and the `AltScreen` value of the view have not changed for `settleDelay`. Text that changes inside the dock does not reset the wait. When a message changes one of them, `Update` sets `m.out.settling`, increments `m.out.settleN`, and batches `tea.Tick(settleDelay, ...)`, which sends `settledMsg{n}` (committed-row rule). `const settleDelay = 3 * time.Second / framesPerSecond` is 50 ms, three frames of the renderer, which draws 60 frames a second (`bubbletea/v2@v2.1.1/renderer.go:13`). In measured runs under tmux 3.6 with Bubble Tea v2.1.1 on 2026-11-12, waits of 0 ms and 5 ms failed, and waits of 17, 34 and 50 ms did not. Upstream issues `charmbracelet/bubbletea` #1736 (no way to order `tea.Println` with the frame flush) and #1881 (a print returned from the update that leaves the alternate screen is lost) were open on 2026-11-12, so no API orders a print with a flush. The reporter of #1881 found that PR #1741 printed in tmux 3 of 3 times, where v2.1.0 printed 0 of 3. PR #1741 is not in v2.1.1. The five print rules stand until a measured run on a later release shows which rule that release makes unneeded. Upstream issue #1885 reports that full-width lines lose their last cell, which is why printed lines stop one cell short. A `settledMsg` whose `n` equals `m.out.settleN` clears `settling`. So a print never runs against a frame that the renderer has not drawn: not against a taller dock that has just closed, and not inside the alternate screen that has just closed.
3. Frozen frame. While `m.out.printing` is true, `View()` returns `m.out.frozen`, the `tea.View` that `drain` stored when the print started. `Update` applies every message as usual. On `printedMsg`, `printing` clears. `Update` then runs the geometry check of every message, as the committed-row rule defines. The bound of a print comes from the frame on screen, so that frame must not change until the print has landed. A frozen view gives that with one branch in `View()` and no second message queue. A window size message during a print still changes the window, so a chunk can be sized for the old window. The Assumptions name this case. The frozen view is needed. Measured on 2026-11-12 with the real program in `testing/synctest` against the `x/vt` emulator, 3 passes of 20 runs for each case under the race detector: when a message grew the dock from 3 to 12 rows while a print of 20 rows was in flight, the history held dock lines in 60 of 60 runs without the frozen view and in 0 of 60 with it. When the dock shrank while a print that fitted was in flight, 0 of 300 runs failed with or without it. A model of the whole state machine (rows queue, one update function checks the geometry and is the only caller of the printer, frozen view) then ran 100 random seeds of 40 steps in the same harness: no seed gave a wrong screen or history, and with the settle wait removed all 100 did. `TestDockGrowDuringPrintKeepsHistoryClean` (Terminal step 3) keeps the grow case.
4. Room. One print holds at most the window rows minus the dock rows, so `takeChunk` stops at `m.screen.height - len(m.dockLines())`. The dock is at most the window rows minus one, so a print always has room for at least one row. In a window of fewer than 2 rows `dockLines` returns no lines and `View()` returns the empty view, so the dock has no rows and a print has room for the rows of the window. At program start the window height is 0, so nothing prints before the first `tea.WindowSizeMsg`. That message changes the window size, so it also starts the settle delay (rule 2). The renderer's buffer has the full window height until its first flush (`bubbletea/v2@v2.1.1/cursed_renderer.go:48`, `:345`), so a print before that flush would be wrong.
5. First row first. Until the first row has printed, `View()` returns an empty view, unless `m.leaving` is set. `m.out.started` is set on the first `printedMsg`. The welcome row is the first row, because the `initialize` result commits it before any thread row (Terminal step 37). The reason is the `scroll-on-clear` measurement in the fact table.

`Update` is the only caller of `drain`, so no other code starts a print. Closing the review has no print code of its own: the view changes, the frame settles (print rule 2), and `drain` prints the rows that waited. While a print is in flight, `View()` returns the frozen view (print rule 3). Keys: `item:<threadId>:<itemId>`, `block:<threadId>:<itemId>:<n>` (the n-th final block of a streamed item), `plan:<turnId>:<n>`, `note:<n>`, `group:<turnId>:<n>`, `shell:<n>`, `welcome`, `exit`, `thread:<threadId>:<n>` (`<n>` is `m.out.loads`, Step 3), `review:<threadId>:<itemId>` and `review:<threadId>:<turnId>` (the edit-review workstream, Step 7). `m.out.printed` is never reset: every key is unique for the life of the program. Each key carries a thread id, a turn id or a counter that only grows, except `welcome` and `exit`, which print once. No code outside `drain` calls `tea.Println`.
