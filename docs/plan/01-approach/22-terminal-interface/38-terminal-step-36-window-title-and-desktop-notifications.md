#### Terminal step 36. Window title and desktop notifications

- `notify.go`: `View.WindowTitle = sanitizeText(m.conn.product + " · " + m.thread.title + " · " + stateWord(m.thread.state, m.thread.lastTurn))` (`bubbletea/v2@v2.1.1/tea.go:143`), sanitised. `View` also sets `ReportFocus = true` (`tea.go:184`), because Bubble Tea practice rule 21 needs focus reports.
- The field `screen.notifications` (declared in the Structure) holds the `notifications` setting (Schemas; protocol Steps 8 and 10). `applyConfig` (Step 9) sets it from `Config.Notifications`. Its default is true. When it is false, no desktop notification is sent at all.
- `func (m *model) notify(text string) tea.Cmd` returns nil while `notifications` is false, and while the window is focused. Otherwise it returns `tea.Raw(seq)` (`bubbletea/v2@v2.1.1/raw.go:33`), where `seq` is the bell (`"\a"`) when `TMUX` is non-empty, else `ansi.DesktopNotification(text)` (`x/ansi@v0.11.9/notification.go:30`) when `TERM=xterm-kitty`, `ansi.Notify(text)` (`notification.go:16`) when `TERM_PROGRAM` is `iTerm.app`, `WezTerm` or `ghostty`, and the bell otherwise. The environment comes from the stored `EnvMsg` through `m.screen.env.Getenv`.
- Fired on turn end (`<product>: <word> · <title>`, where `<word>` is `Done`, `Failed` or `Stopped` from `stateWord`), approval request (`<product>: Waiting for approval · <title>`) and ask request (`<product>: Waiting for your answer · <title>`), each through `notify`.
- Thread load. `applyResumed` (`commands.go:557`), when the loaded thread id differs from the followed one, commits the key `thread:<threadId>:<n>`, where `<n>` is `m.out.loads` after this load, with one separator row `── <title> ──`. This step owns the text of that key. Step 3 only calls `commit` with it, and the separator is the only row under it. `<title>` is `threadTitle` (`model.go:569`), cut to `width - 1` cells with `fit`. Then the thread's rows commit as usual. Nothing is cleared. Earlier keys stay in `m.out.printed`, and no row is printed again (cross-phase decision 36). The welcome row (step 37) is printed once, for the first thread only.
