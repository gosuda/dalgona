- Validation after this step. `mode` must be `find`, `grep` or `symbols`: `search: mode must be find, grep, or symbols`. `pattern` must not be empty in `find` and `grep`: `search: pattern must not be empty`. Each name in `kind` must be in `symbolKinds`: `search: unknown kind NAME`. `kind` applies only to `symbols`: `search: kind applies only to symbols`. A pattern that is not literal must pass the anchor check of decision 7: `search: name patterns cannot use ^, $, \A, \z, \b or \B; match the name only`.
- Candidates. `entries` come in display-path order. An entry is a candidate when its extension belongs to a language that has a definition query. An entry whose language is syntax only counts as a skipped syntax-only file. An entry with no language is skipped without a footer. With a non-empty pattern, `scanFile(entry, matcher)` (`engine.go:287`) must return a match, where `matcher` is `grepRegexp(args)` (`engine.go:258`), and its bytes are reused. Without a pattern, the file is read with `readCapped` (`engine.go:317`) and must pass `searchableText` (`engine.go:313`). Entries of supported languages in scope are counted for the empty-reply text. `parseCandidates` in `parse.go` is the one candidate listing of the parse modes: `func parseCandidates(ctx context.Context, entries []fileEntry, glob string, accept func(display string) bool) ([]fileEntry, error)`. It keeps each entry for which `accept` returns true, then, when `glob` is not empty, the entries that `matchingFiles` (`engine.go:273`) keeps for `glob`. It returns `ctx.Err()` when `ctx` has ended. `symbolsMode` passes an `accept` that holds when `syntax.ForPath` finds a language, and it counts each kept entry whose language has no definition query (`Language.HasDefinitions`, Code symbols step 1) as syntax only. `syntaxMode` passes an `accept` that holds when the lower-cased extension of the entry is one of `lang.Extensions()`.
- Dispatcher. One goroutine walks the candidates in order. For each candidate it calls `now()` once, and only there. If `now().Sub(start) >= parseBudget`, the candidate and every later candidate count as stopped. Otherwise, if the candidate is larger than `parseMaxFileBytes`, or the number of dispatched candidates has reached `parseMaxFiles`, or the running byte total plus its size is above `parseMaxBytes`, the candidate counts as not parsed. Otherwise the dispatcher sends it to a worker.
- Workers. `parseWorkerCount` workers each keep a map from language name to `*syntax.Parser`, created with `Language.NewParser()` on first use. A worker calls `Symbols(ctx, data)` for its candidate and stores the result at the candidate's index. An error ends the call with its text.
- Output. Rows come first, in candidate order and then line order. A symbol is a row when its kind is in `kind`, when `kind` is empty, and when its name matches the matcher. Each row is `PATH:START-END: KIND TEXT`, with two spaces before the path for each level of depth (decision 18). The text is the first source line of the definition, cut by `cropMatch`. `limit` caps the rows. Then the footers follow in the order of decision 15: the `[Parse: ...]` lines in path order, `[Not parsed: N files. Narrow path or glob.]` when the caps stop files, `[Syntax only: N files. Use mode syntax with lang.]`, `[Stopped: N files not parsed. Narrow path or glob.]` for the budget, and `[Truncated: N more symbols]` last.
- Empty replies. With no rows and a non-empty pattern: `No matches for PATTERN. Searched N files of supported languages.` With no rows and an empty pattern: `No symbols. Searched N files of supported languages.`
- Flatten rule and kinds: as in Step 1, with `kindOf` from `internal/syntax`. Unknown kinds are not possible for the shipped queries. An unknown kind is a package error and not a user call (decision 5).
- Specification text, the section `## Symbols and syntax` in `docs/spec/search.md`:
  - The symbols mode MUST list the definitions under path as `PATH:START-END: KIND TEXT` rows.
  - A child row MUST be indented by two spaces for each level of nesting.
  - Definitions inside a function, method, constant, or variable MUST NOT be listed.
  - The symbols mode MUST parse only files whose extension belongs to a language with a definition query.
  - The `.h` extension MUST belong to the `c` language, and it MUST NOT select `cpp`.
  - A non-empty pattern MUST first select the files in which some line matches it.
  - A name pattern that is not literal MUST NOT use `^`, `$`, `\A`, `\z`, `\b`, or `\B`.
  - The symbols mode MUST parse at most 256 files and 1 MiB of source in one call.
  - A file over 256 KiB MUST NOT be parsed.
  - Each parse MUST stop after 2 seconds, and a call MUST stop starting new files after 10 seconds.
  - The search child MUST stop after 30 seconds.
  - A file whose parse stopped MUST give no rows, and it MUST appear in a `[Parse: stopped, no rows:]` line.
  - A file whose tree has syntax errors MUST keep its rows, and it MUST appear in a `[Parse: syntax errors, rows kept:]` line.
  - Symbol rows MUST be sorted by path and then by start line.
  - Symbol rows MUST NOT carry snapshot tags.
  - The `pattern` argument MAY be empty only in the symbols mode.
