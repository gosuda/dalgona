- Change: `definition` matches names as `symbols` does, with `kind`, `literal`, `ignore_case`, `path` and `glob`. For each matching definition the output is one header row, `PATH:START-END: KIND TEXT` with the depth indent, then one body row for each line from its start line to its end line. A body row is `PATH:LINE: TEXT` (decision 18), and its text is the output of `cropMatch`. A header row is printed only when at least one of its body rows is printed. `limit` caps the body rows for the call, with a default of 200 (`json.go:88`) and a maximum of 1000 (`json.go:104`). When the cap cuts a body, the body ends with `[Truncated: N more lines]`, where N counts every body line not printed. Definitions after the cut give no rows. Headers and footers do not count against `limit`. A line can appear under two headers when one definition contains another. Each file that has printed rows receives one capture: its whole data, with the printed lines that were printed in full as shown ranges, built with `appendShown` (`engine.go:403`). `makeResult` (`search.go:124`) then adds the `[PATH#tag]`, `[PATH#version]` and `[PATH@ref]` lines.
- A body row can be cited by a later `patch` call, because it has the grep row form and capture data. A header row can be read with the `read` tool, with offset START and limit END minus START plus 1. The `read` tool accepts a limit of at most 2000 lines (`internal/tool/read/read.go:46`, and the refusal at `read.go:396-397`), so a definition longer than 2000 lines needs one `read` call for each 2000 lines.

- Specification text, in `docs/spec/search.md`:
  - The definition mode MUST print each matching definition as a header row, followed by its source lines.
  - Each body row MUST use the form `PATH:LINE: TEXT`.
  - The definition mode MUST cap the body rows at `limit` for one call.
  - The definition mode MUST NOT accept an empty pattern.
  - The find and grep modes MUST return at most `limit` results, and the definition mode MUST print at most `limit` source lines. This sentence replaces `Search MUST return at most `limit` results.` from Specifications step 31.
