#### Outcome of the edit-review workstream

When dalgona has `[edit_review] enabled = true`, a decision model judges two units. The edit unit is each call of an edit-class tool (`patch`, `apply_patch` or `rewrite`) that adds lines. The turn unit is the whole turn, judged once before the turn ends. Each unit asks independent `noul` questions. A large edit unit sends up to 8 requests, called parts, and the turn unit sends one. The primary question `sound` judges the diff against `task`. The other questions each name one defect in one dimension: correctness, completion, scope, complexity, slop, concurrency, performance, security, design, visual, and layout and motion. Each defect score falls in one of three bands: 0.9 or more is a flag, 0.5 up to 0.9 is uncertain, and under 0.5 is clean. Two keys decide what reaches the working model. A flag speaks only when its question is a speaker and the `sound` score of the same part is under 0.5. The built-in speakers can be replaced with `[edit_review] feedback`, and the held-out measurement can change them. A speaking edit flag adds a fixed `<edit-review>` block after that round's tool results, at most three times per turn. A speaking turn flag adds one `<turn-review>` block, and the turn goes on for one more round, once. The verdict is journaled as `tool.judged` after `tool.completed`, or as `turn.judged`, and shows in the terminal and the browser. The review fails open. A judge error, a timeout, or a missing model fails its request, and a failed request fails its part. A unit is journaled as `error` only when every part fails or when no request is sent. It never blocks an edit. Each edit unit has one 8 s limit, so a turn with edits in several rounds can wait up to 8 s in each round. The turn review has its own 8 s limit. Recovery never judges. Raw secrets never reach the judge. A frozen, labelled set and a measurement file measure each question's held-out precision before anyone proposes turning the feature on by default.
