- Symbols (package `textdiff`):
  - `const Limit = 1 << 20`: the largest side that is diffed. A side larger than `Limit` is not diffed: edit review skips that file (`classifyReviewFile`, Step 4). Other callers, such as `ApprovalFile.TooLarge`, cite this constant and keep their own skip branch.
  - `type Stats struct { Added, Removed int }`: the number of `+` and `-` lines over all hunks.
  - `func Unified(oldName, newName string, pre, post []byte, context int) (string, Stats, error)`. It calls `udiff.ToUnified(oldName, newName, string(pre), udiff.Lines(string(pre), string(post)), context)` (`unified.go:36`, `ndiff.go:16`), which returns the unified text with `context` lines of unchanged text around each hunk. The edit unit passes 3, and the turn unit passes 0. It wraps the error of `ToUnified` as `diff <newName>: ...`. It then counts the lines after the two header lines (the `---` and `+++` lines that `unified.String` writes) whose first byte is `+` (added) or `-` (removed). Equal inputs return `""` and `Stats{}`. The `\ No newline` marker starts with a backslash, so it is not counted.
  - No other symbol. The hand-written algorithm, its constants and its helpers are deleted.
- Facts checked in go-udiff v0.4.1 (module `github.com/aymanbagabas/go-udiff@v0.4.1`, file `unified.go`):
  - `String` writes `--- <label>` and `+++ <label>` (`unified.String`, `unified.go`), so callers pass `a/<path>`, `b/<path>`, or `/dev/null` as the labels.
  - The hunk header writes a count only when it is above 1, and an empty side at line 1 is written `0,0` (`unified.String`, `unified.go:213`).
  - `DefaultContextLines` is 3 (`unified.go:17`), and the hunk merge gap is `contextLines * 2` (`toUnified`, `unified.go:106`), so a count of 0 gives hunks that hold only changed lines.
  - `String` writes `\ No newline at end of file` after each line without a final newline (`unified.String`, `unified.go:261`), so `Unified` appends nothing.
- Tests (`internal/textdiff/textdiff_test.go`, cross-phase decision 42): `TestUnifiedCountsAddedAndRemovedLines`, `TestUnifiedCountsLinesThatStartWithDashes`, `TestUnifiedDoesNotCountTheNoNewlineMarker`, `TestUnifiedEqualInputsReturnEmpty`, `TestUnifiedContextZeroHasNoContextLines`. The four older tests pass context 3, and their cases are: for pre `a\nb\n` and post `a\nc\nd\n`, `Stats{Added: 2, Removed: 1}`; for pre `-- x\n` and post `-- y\n`, `Stats{Added: 1, Removed: 1}`; for pre `a` and post `b` (no final newline), `Stats{Added: 1, Removed: 1}` and the output contains `\ No newline at end of file`; for equal inputs, `""` and `Stats{}`. The expected value follows from the rule that a context count of 0 writes no unchanged line.
