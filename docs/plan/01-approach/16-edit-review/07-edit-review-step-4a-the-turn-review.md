  - `type turnDiff struct { paths, skipped []string; files []reviewFile; err error }`.
  - `func (w *worker) collectTurnDiff(records []event.Seqd) turnDiff`: walks the records from the open turn's `turn.started` on.
  - `func (w *worker) judgeTurn(ctx context.Context, task string, diff turnDiff, start time.Time) (event.TurnJudged, bool)`: creates `tctx` under `w.t.host.reviewTimeout`, calls `diffFiles(diff.files, 0)` and `turnRequest(task, diffs)`, sends the one request with `judgeParts`, and maps the outcome to the fields of `TurnJudged`. It returns `false`, and journals nothing, when the pre-filter skips the turn.
  - `func turnRequest(task string, files []fileDiff) (judgeInput, int, error)`: pure. It joins each file's header and hunks into one diff, measures the state with empty diffs, and gives the room left under `reviewRequestLimit` to `shareRoom`. The state holds `task` (left out when empty) and `files`, and no `tool`, `part`, or `omitted_hunks`. Its questions are `turnQuestionSet()`. It returns the sum of `added` as the int. When the request is still above `reviewRequestLimit`, it returns the error `review: turn state exceeds the request limit`.
  - `func shareRoom(diffs []string, room int) []string`: pure. Each length is the encoded length after JSON escaping, so the shares bound the request body. For diff `i` of `n` diffs, its share is the room left divided by `n - i`. A diff that fits its share is kept whole, and its unused share goes to the diffs after it. A diff that does not fit is cut by `truncateDiff` to its share.
  - `func truncateDiff(diff string, limit int) string`: returns `diff` when it fits. Otherwise it cuts after the last line end, then moves the cut back to an earlier line end until the kept text, the marker `[truncated: <n> more bytes of this diff]`, and its newline fit in `limit`, where `<n>` counts the removed bytes. It returns the marker alone when no line end fits, and an empty string when the marker does not fit. It replaces `cutDiff` of Step 4.

Behaviour:
- Position. A reply with no tool call reaches the `!needsModel` branch of `loop` (turn.go:150). In that branch the order is: (1) `turnReview`, which waits at most 8 s; (2) `w.boundary`, which runs the advisor wait and has no time limit of its own (turn.go:243-247); then the loop returns `completed`; (3) `end` calls `notifyTurnEnd`, which runs the script `turn_end` hook (`notifyTurnEnd` in `internal/agent/turn.go`); (4) `settle` journals `turn.completed`. The review therefore runs before the advisor wait and before the `turn_end` hook, and both see its journal event.
- Gate. `turnReview` returns `(false, v.head())` without any work unless all of these hold: `w.t.host.cfg.EditJudge` is set; `w.eligible` is true (an edit unit of this turn passed the pre-filter in Step 4); `!w.recovering`; `!w.reviewed`; the turn id is not in `v.state.JudgedTurns`; and `w.task()` (gate.go) is not empty. The reason for the task rule: the only turn speaker, `incomplete`, needs a task. Once the gate passes, it sets `w.reviewed = true` before any journal write.
- Diff. `collectTurnDiff(v.records)` walks the records from the open turn's `turn.started`. For each `event.FileChange` of an edit call of this turn, in journal order, the first counted change of a path gives the pre-image (`PreBlob`). A nil `PreBlob` means the file did not exist, so the change is `add`. The last counted change of the path gives the post-image (`PostBlob`, the staged masked blob that the protocol workstream, Step 5 adds to `event.FileChange`). A change counts only when its call's `tool.completed` has `OK` true, and the pre-image comes from the first counted change. `paths` lists each path with a counted change once, in first-edit order, at most 64 entries. Each path passes through `w.t.host.mask` first, because the journal holds raw paths from `tool.started` (tools.go:319). `files` leaves out a path whose pre-image and post-image are equal. `skipped` lists each path of `paths` whose last change has no `PostBlob`, so `skipped` never names a path that `paths` leaves out. Blobs are read through `w.t.host.journal.Blob` and are masked already. The other paths go through `classifyReviewFile`, so a `large` file is left out of `files` and sets `truncated`, and a `binary` file stays as a `[binary file]` entry, as in the edit unit. A blob read error sets `err`. `judgeTurn` makes the file diffs with context 0, so they hold changed lines only.
- Pre-filter. When `err` is nil and `turnRequest` gives `added == 0`, or the turn has no file, the turn is not judged and nothing is journaled.
- State and request. `turnRequest(task, files)` builds the one request of `turnQuestionSet()`. Each file keeps its header and its share of the room from `shareRoom`. The turn request has no `tool` key and is never split into parts. When `shareRoom` cuts a diff, the turn unit is `truncated`. Masking and `requireMasked` are those of the edit unit.
- Wait. `judgeTurn` sends its one request under `w.t.host.reviewTimeout` (8 s by default), through `judgeParts`. The loop waits in the foreground.
- Journal. `turn.judged` is appended with `context.WithoutCancel(ctx)`:
  - `clean` or `uncertain`: `scores`, `paths`, `skipped`, `truncated`, `by`, `elapsed_ms`. No `spoken` and no `feedback`. A `clean` verdict with `truncated` set is written as `uncertain`.
  - `flagged`: the same fields plus `flags`. `spoken` is `reviewSpoken(scores, flags, EditFeedback)`. `feedback` is true only when `spoken` is not empty. For the turn unit, `spoken` is empty when `truncated` is set, because `incomplete` cannot be judged on a cut diff.
  - `error`: `error` through `reviewErrorText`, plus `paths`, `skipped`, `truncated`, `by`, `elapsed_ms`. No scores. A timeout gives `part 1 of 1: review timed out after 8s`. A blob read error gives the read error text. An interrupt gives `part 1 of 1: review: the turn was interrupted`. `truncated` follows the rule of `tool.judged`.
- Speaking. When `feedback` is true, `turnReview` returns `resume = true` and the head of that append. The next pass reads the `<turn-review>` user message that the transcript builds from the event (Step 5). `needsModel` is then true, so the same turn goes on, and the model is called again.
- Not speaking. `turnReview` returns `resume = ctx.Err() != nil` and the head of the append, or `v.head()` when nothing was appended. The boundary then runs with that head.
- Append failure. A failed append logs a warning, journals nothing, and returns `resume = ctx.Err() != nil`. `w.reviewed` still stops a second run in this drive.
- Second end. A later tool-free end finds `w.reviewed` or the turn id in `JudgedTurns` and returns at the gate. No second turn review runs.
- Interrupt during the wait. `askPart` returns `errReviewInterrupted`, and the event is journaled as `error`. `resume` is true, so the loop's top check (`ctx.Err()`, turn.go:143) ends the turn as `interrupted`. The boundary does not run.
- Recovery. `recoverTurn` sets `w.recovering` first, so recovery never runs the turn review. A turn that recovery restarted gets no turn review, even for edits made after the restart. Those edits still get the edit review of Step 4.
- Continuation. An advisor continuation (advisor.go:46-50) and an auto-continue (turn.go:293-297) start a new turn id on a new worker (`spawnContinuation`, `spawnTurn`, turn.go:72-77). That worker starts with `eligible` false, so its review covers only its own edits.
- Caps. At most one `turn.judged` with feedback per turn id. The turn block does not count toward the three edit feedback blocks.
