#### Decisions of the edit-review workstream

1. Independent `noul` questions, with `sound` as the primary question, instead of one `choice` verdict. Rival: one `choice` question `verdict` with options `ok | broken | incomplete | off_task`.
   - A choice makes the options exclude each other. Two defects in one edit then split their probability, so neither crosses a threshold. A `noul` gives each defect its own probability of yes.
   - The `llm:` adapter is the default without stored OpenRouter credentials (`internal/app/decider.go:69-72`). It returns a choice as a bare label with no probabilities (`internal/decide/llm.go:153-156`). A `noul` returns a number under both adapters (`internal/decide/llm.go:157-160`).
   - Each `noul` gets its own precision row in the measurement, and the ratchet can drop one question without touching the others.
   - The direction is reversed on purpose. Approval questions mean "yes is safe", and they allow at a score of at least the threshold. Review questions mean "yes is a defect", and they flag at a score of at least 0.9. A missing or failed answer fails its part, and a failed part never speaks, so the review fails open. A unit gets the `error` verdict only when every part fails. `sound` is the one question where yes is good. It gates speech and never flags.
   - The Decisions API answers every question in one request (`internal/decide/json.go:57`, `writeQuestions`), so the whole set costs one round trip.
2. Questions ask for evidence a reader can check in the diff, one set for each dimension. Rival: a general "introduces a bug" question. The section "Design record" of this plan records that a decision model judging single functions flagged about 8 percent of sound code, and none of its 30 strongest flags held. Subjective correctness questions fail that way. Each question names one defect that the shown lines can show. The sets follow the dimensions in the Outcome.
3. The judge sees a unified diff, not the whole post-image. The edit unit's diff keeps 3 context lines, and the turn unit's keeps none, because `textdiff.Unified` takes the count as its last parameter. Rival: send the whole post-image. Every question can be answered from the diff, and a whole file costs more and costs more tokens for the same answers. The turn unit's diff is cumulative over the turn, so it sends changed lines only, which keeps it in one request.
4. The written file is read right away, the judge runs in the background, and the result is collected at the end of the round. Rival 1: judge each call before the next one runs. That adds up to 8 s per edit, one after another. Rival 2: put the verdict inside the `tool.completed` output. The journal is append-only and `tool.completed` is written before any verdict exists.
5. Recovery writes no `tool.judged` and no `turn.judged`, and it runs neither review. Rival: write a made-up `error` verdict on recovery. Recovery cannot know whether review was on, or whether the pre-filter would have skipped the edit, so a made-up event would misreport. A recovered turn also skips the turn review, through a flag on the worker (decision 24 of this workstream).
6. Edits skipped by the pre-filter write nothing, and a turn with no judged edit writes no `turn.judged`. Rival: a `skipped` verdict on every edit. That adds an event to every edit that has nothing to judge. Errors and truncation still stay visible in the counts: `error` verdicts and the `truncated` field are journaled, and the measurement reports errors.
7. Config is a new `[edit_review]` table with `enabled` (default `false`) and `feedback`, dalgona only. Rival: a top-level boolean `edit_review`. The scope asks for a table, and a table matches the existing `[approval_decider]` shape. The model comes from `[approval_decider].decider`; its `threshold` does not apply to review.
8. The per-turn cap is decided when results are collected and recorded in `feedback`. Rival: work out the cap while building the transcript. The transcript must rebuild old journals the same way even if the cap rule changes later.
9. Feedback is its own user message after the round's tool results. Rival: add it to the end of the tool result text. That is impossible because the journal is append-only.
10. The browser and terminal get live notifications, `dalgona/tool/judged` and `dalgona/turn/judged`, with a server-built `summary`. No extra field goes on the Codex `fileChange` item on the wire. The browser keeps the verdict in its own transcript state (Step 8). Rival: add a `review` field to the item. That breaks the Codex ThreadItem shape the clients rely on. Consequence: `thread/read` history does not show verdicts. The model still saw the feedback.
11. The terminal prints a row for `flagged` and `error` at every verbosity, and for `uncertain` only at verbosity `high`. The browser shows every verdict. Rival: print every verdict in the terminal. Rows in the scrollback are written once and stay. A clean row would add one more row for every edit, and an uncertain row is a guess, so it shows only at verbosity `high`.
12. One diff package, `internal/textdiff`, built on `github.com/aymanbagabas/go-udiff` v0.4.1. Rival 1: run `git diff --no-index`. Runners may not have git, and the pre-image is in the blob store, not the workspace. Rival 2: a hand-written Myers diff. It repeats an algorithm that go-udiff already provides, and it needs its own tests. Rival 3: `github.com/sourcegraph/go-diff`. It is already an indirect dependency (`go.mod:252`) but it parses diffs; it does not compute them. go-udiff computes the diff and writes the unified format (`unified.go:22`). `github.com/hexops/gotextdiff` (`go.mod:167`) is replaced by it.
13. Three thresholds, one constant each: flag at `reviewFlagThreshold` (0.9), uncertain from `reviewUncertainThreshold` (0.5), and the `sound` key at `reviewSoundThreshold` (0.5). Rival: a separate flag threshold per question. There is no measurement yet to set different values; the ratchet in step 9 is where that data comes from.
14. Masking: every string that enters the judge state is masked first, and a final check refuses a state that masking would still change. Rival: mask only the final JSON. Secrets that contain quotes are escaped inside JSON, so a mask over the JSON can miss them.
15. Scope of which edits are judged. Edits from the working model's calls in every thread of the host are judged, including subagents. Edits that recovery runs or replays, edits made inside a script, and Cursor in-band calls are not. The turn unit covers the same edits. A turn is judged when at least one of its edit calls was judged.
16. Timeout is an unexported `Host.reviewTimeout`, which defaults to the constant `reviewTimeout` (8 s), for both units. The parts of one edit unit share that one limit. Rival: a config key. No user needs to set it, and tests need a short one. The boundary wait has no deadline of its own (`internal/agent/turn.go:243-247`), so the turn review adds one.
17. Two keys: a flag speaks only when its question is a speaker and the `sound` score of the same part is under 0.5. Rival 1: a flag speaks alone. Rival 2: one `choice` verdict whose probability of sound gates the flags. Rival 2 needs probabilities, which the `llm:` adapter does not return (`internal/decide/llm.go:153-155`). Reason for the second key: `sound` reads the whole diff against `task`, so a single defect score that `sound` does not share is held back. The measurement in step 9 has not run, so this reason is not measured.
18. Speakers: a built-in set, which the owner's `feedback` key replaces and the measurement can change. The candidate set is `broken_syntax`, `lost_code`, `placeholder`, `off_task`, `narration`, and the turn question `incomplete`. No candidate speaks until the measurement in Step 9 names it. These are the questions whose evidence a reader can check in the diff without reasoning about behaviour. Rivals are in decision 19 of this workstream. The owner's key `[edit_review] feedback` replaces the set when it is present. The measurement may add a question or remove one.
19. Why this feedback policy. Options: every flagged question speaks; none speaks; only measured questions speak; the checkable questions are the candidates, and the measurement decides which of them speak. The last one is chosen, and no candidate speaks until the measurement names it. The measurement objection removes "every flagged question": the section "Design record" of this plan states that an earlier measurement found that a decision model judging single functions flagged about 8 percent of sound code, and none of its 30 strongest flags was real. Dieter Rams (rank 5) removes "none" and "only measured": each cuts the part the owner asked for, because the measurement needs credentials for the decision service. The owner's `feedback` key keeps that part available without a measurement. Feynman's objection to the chosen option is met by keeping every candidate silent until the measurement names it, and by letting the measurement remove any question from the set.
20. An uncertain band. Rival: a binary result, flagged or clean. A score from 0.5 to 0.9 would then be either a flag or silence. Reason: a mid score is information for the terminal at verbosity `high` and for the browser, but it cannot speak, so the model never acts on a guess. The verdict `uncertain` is journaled.
21. One failed answer fails its part. Rival: per-question scoring, which keeps the other scores when one answer is missing. Reason: `scoreAnswers` already rejects a missing or out-of-range answer (`internal/agent/decider.go:124-126`), and both decide adapters already fail the request on a missing answer (`internal/decide/decisions.go:238`, `internal/decide/llm.go:125-127`). The review reuses these rules, so the decide package does not change. Consequence: the part adds no scores, and the parts rule of this step decides the unit.
22. A turn unit: one review of the whole turn before the turn ends, once per turn. The owner chose it, because it gives the working model one more round, once. Rival: judge each edit only. Reason: the `incomplete` question needs the cumulative diff against `task`, and no single edit contains it.
23. The turn review call sits in `worker.loop`, not in the boundary hook. Rival: `SetBoundaryHook`. That hook has one slot, and the advisor installs it (`internal/agent/advisor.go:10-14`, `internal/agent/advisor/runtime.go:76`). A second install replaces the advisor's hook (`internal/agent/advisor.go:12`). `worker.loop` calls the review directly, before the boundary call at `internal/agent/turn.go:154`. When the review speaks, a user-role message is journaled before that point, the model runs again, and the same turn goes on because `needsModel` at `internal/agent/turn.go:150` is true again.
24. `turn.judged` is folded into `State` through `JudgedTurns`. Rival: no event, and an in-memory flag. Recovery must see whether the turn was judged. Recovery metadata folds over the full journal (`docs/spec/events.md:79`), and model context reads the active path only (`Thread.messages` in `internal/agent/context.go`). The loop checks `JudgedTurns` before it calls the review, so a turn gets at most one turn review. A recovered turn skips the review through a flag on the worker (`openLocked` in `internal/agent/thread.go`, `recoverTurn` in `internal/agent/recover.go`).
25. Split a large edit into parts under a request limit of 30,000 bytes. Rival 1: cut the state at 49,152 bytes. That crosses the line of about 32,000 bytes in the OpenRouter guide (`https://openrouter.ai/docs/guides/community/jev.md`), above which a request runs in TypeSafe's long-context mode, which is slower and less accurate. The guide does not say whether questions count toward those bytes, so the limit counts the state and the questions. Rival 2: one request for each file. Each request repeats the task and the question set, which is up to 7,364 bytes, so a ten-file edit pays that cost ten times. Rival 3: a parser for each language to find split points. Each language adds a dependency. The chosen rule packs whole hunks in call order, splits a hunk only when no empty part can hold it, and sends at most 8 parts, 4 at a time, under one 8 s limit. Consequence: a file that spans parts reaches the judge in each part, and each part speaks on its own `sound` score. The turn unit stays one request, because `incomplete` needs the whole turn. An estimate, not a measurement: if a token is 3 to 4 bytes, one full part is 7,500 to 10,000 input tokens, which costs 0.000315 to 0.000420 USD at the listed price of 0.042 USD for each million input tokens.
