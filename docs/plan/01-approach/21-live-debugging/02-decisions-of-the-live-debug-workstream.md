#### Decisions of the live-debug workstream

| Decision | Rejected rival | Reason |
|---|---|---|
| The server lives in `internal/llmstub` (library, standard library only) with its command in `internal/llmstub/cmd/llmstub`. | A product-style binary under `cmd/llmstub`. | `just build` builds `./cmd/...` into `bin/`, and `cmd/` holds only shipped products. A test-support binary must not appear next to them. |
| The script is one JSON file read with `encoding/json/jsontext`. | TOML, or Go code fixtures. | The repository rule puts JSON on `jsontext`. The SSE payloads are JSON already, so tool arguments are written once in the same syntax. |
| A turn is chosen by matching the request's last message (`when.user`, `when.tool_result`, `when.any_text`). Turns repeat unless `once` is true. | A strict FIFO queue of turns. | Live sessions send requests in an order the script cannot predict, such as subagents, compaction and retries. A queue would desynchronize on the first extra request. `once` still gives exact sequences such as 429 followed by success. |
| An unmatched request gets HTTP 400 with code `llmstub_unmatched`. | A default reply, or a 500 response. | A 400 is terminal (`docs/spec/providers.md:79`: other errors MUST be terminal), so the gap shows once in the UI and in the stub log. A 500 would be retried three times, and a default reply would hide the gap. |
| The stub records every request to JSONL (`-record`). | Asserting only on screens. | Transcript assertions such as the paste content, multi-line text, effort and tool results reaching the model need the bytes the client actually sent. |
| The cross-check test that proves the stub's frames decode lives in `internal/model/chatcompat` (package `chatcompat`). | A test inside `internal/llmstub` that imports chatcompat. | It reuses `newStreamServer`, `testKey`, `fastRetry` and `collectStream` (`internal/model/chatcompat/chatcompat_test.go:296-330`) without guessing at an exported constructor. The decoder (`decode.go`) is the oracle. |
| `live-check` does not join `just verify`. | Joining it. | The recipe pins the stub to `127.0.0.1:18080`, and `dalgona web` keeps its default `127.0.0.1:7437` (`internal/config/config.go:264`), and the recipe spawns a detached daemon. Two worktrees running verify at once would collide on the ports and fail commits for an environmental reason. The stub's own Go tests use ephemeral ports and already run in `just test`. |
| The recipes own pid files under `/tmp/dg/*.pid` and stop only a pid whose `/proc/<pid>/cmdline` starts with `/tmp/dg/bin/`. Daemons that `Ensure` spawned are stopped with `pkill -TERM -x -f '/tmp/dg/bin/dalgona daemon'`. | Plain `pkill dalgona`. | The product has no pidfile, and the developer's real daemon must never be touched. The exact absolute argv matches because `ensure` passes the resolved absolute executable path (`cmd/dalgona/daemon.go:25-34`). |
| The terminal is driven with the `tui` tool's `send`, `screen`, `shot`, `resize` and `raw` ops. | Its `keys`, `type`, `paste` and `mouse` ops. | Those four ops go through the `OMP_TUI_DEBUG` socket that only omp/pi-tui hosts serve (`.references/oh-my-pi/.omp/tools/tui.ts:1442-1500`). `send` writes raw bytes to the PTY for any app (`tui.ts:1503-1510`). |
| The tool session starts with `bin: "env"` and the variables passed as arguments. | Exporting the variables in the omp process. | The tool has no env parameter. It merges `process.env` with its own `TERM` and `COLORTERM` (`.references/oh-my-pi/.omp/tools/tui.ts:1121-1125,1143`), and setting variables in omp would leak into every other tool. |
| The live run report is written to `/tmp/dg/report.md` and returned to the orchestrator. It is never committed. | A report under `docs/`. | A committed run output would be a saved-output pin and would go stale (`CONTRIBUTE.md:19`). |
| The edit-review judge is `[approval_decider]` set to `llm:local/qwen-test`. | A new `[edit_review]` decider key. | The edit review judge reads its model from `[approval_decider]`. The judge call is the edit-review workstream, Step 4. In `ask` mode the gate asks the human and never calls the decider (`internal/agent/gate.go:104-105`), so approval cards keep working. |
