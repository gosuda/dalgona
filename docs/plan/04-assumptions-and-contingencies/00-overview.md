## Assumptions and contingencies

This plan was written with a read-only repository. No command that changes the tree ran, and no gate ran. Every expected value in a test comes from a contract, a specification or a source that the step names. It was not observed.

Each entry below is either a check that only an outside system or a real run can make, or a settled assumption that no check covers. A check names the step that it guards and the action to take when the check fails. Approval of this plan approves every fallback below that ends in a clear refusal, a notice to the user, or an unchanged default. A fallback never ships a fault that a user can see on the screen. Where a check shows such a fault, the step stops, and the defect loop of the live-debug workstream applies: reproduce, write a failing test, fix.
