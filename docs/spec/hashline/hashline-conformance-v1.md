# Hashline v1: conformance and integration

Status: proposed implementation acceptance suite. Only V01's bounded model was
executed. The product tests below are requirements, not claimed completed work.
Contracts: [Common](hashline-common-v1.md), [Light](hashline-light-v1.md),
[Enhanced](hashline-enhanced-v1.md).

## T01. Oracles and fixtures

Every filesystem test uses a unique test-owned workspace and isolated data root.
Capture exact before/after bytes, path names, journal records, deliveries, source
references, and coordinates. No-write assertions compare paths and bytes, not just
error strings. Do not touch real user files.

Expected results MUST NOT be generated by the implementation being tested. Mapping
oracles use unique occurrence identities, including repeated equal text. Byte
oracles independently split BOM/LF/CRLF. Observation tests instrument final consumer
delivery, not merely the read function. Recovery tests do not assume a terminal
result survived.

No Go test uses these IDs yet. T08 assigns the tests to the gate owner, order 7.

## T02. Reference and grammar tests

| ID | Scenario | Required outcome |
|---|---|---|
| REF-01 | Correct thread/open generation/consumer/path | Reference resolves to its immutable source snapshot. |
| REF-02 | Same reference from another consumer or subagent | Reject binding. No foreign preview. |
| REF-03 | Old host, resume, fork, or clone reuses reference | No write or accidental reference reuse. |
| REF-04 | Eviction followed by new issuance | Old reference remains expired. |
| REF-05 | Counter reaches maximum | Refuse issuance. No wrap. |
| REF-06 | Two revisions have equal bytes/digest | Preserve distinct revisions and intervening lineage. |
| SYN-01 | PUT N, N-M and N.=M equivalent locators | Equal IR and staged bytes. |
| SYN-02 | Quoted paths contain spaces, @, #, ], quotes, backslashes | Decode once without delimiter confusion. |
| SYN-03 | Tagless, old #TAG, invented or latest reference | No implicit current-file interpretation. |
| SYN-04 | Body contains +/-, inner fences, apparent headers | Strip one + only. Preserve body. |
| SYN-05 | Empty PUT, reversed range, count used as endpoint, unmatched envelope | Explicit syntax/range failure. |
| SYN-06 | LF/CRLF framing with no final framing LF | Identical intended source bytes. |
| SYN-07 | NEW with blank row, trailing blank row, nonempty row | Exact creation-byte rule. |
| SYN-08 | Body length differs from source range length | Valid replacement. Endpoint is not a body count. |

SYN-07 follows the NEW creation-byte rule in C11 of [Common](hashline-common-v1.md).

## V01. Executed bounded model

[verify_model.py](verify_model.py) models range/gap mapping with unique occurrence
IDs. Its report is [verification.json](verification.json). Run from `docs/spec/hashline`:

```sh
uv run --no-project --python 3.12 verify_model.py
```

Actual runs used available interpreters through `uv --python` in the conversation
runtime and Codexify's private scratch workspace. Both returned exit 0 with the
same counts. The exported script was formatted and checked with Ruff through
Codexify. No product Rust suite was run.

`just hashline-model` fails when the verifier output differs from `verification.json`. When `CI` is `true` and `uv` is missing, `just hashline-model` fails. Otherwise, when `uv` is missing, `just hashline-model` prints `hashline-model: skipped, uv is not installed`. It then exits with status 0.

| Lane | Cases | Accepted mappings |
|---|---:|---:|
| One splice, source length 0-8, insert length 0-3: ranges | 14,178 | 5,676 |
| Same bounds: gaps | 4,335 | 2,400 |
| Two splices, initial length 0-5, each insert length 0-2: ranges | 62,621 | 17,824 |
| Same bounds: gaps | 28,539 | 9,940 |
| Total | 109,673 | 35,840 |

Eight additional checks cover exact equal-text/wrong-occurrence behavior, known
edit-then-undo, range boundaries, protected gap neighbors, empty/EOF gaps, abstract
request cutoffs, profile subset behavior, and expanded EOF footprints.

This bounded model assumes accurate recorded effective splices. It does not test
real byte tokenization, filesystem identity, parser/AST behavior, crash journaling,
resource allocation, message delivery, or live-model results. Abstract coverage
checks are not integration tests. This is not an unbounded proof or a benchmark.

The previous chat's 15,048-case claim lacked a reproducible artifact in the
provided context. The fresh script and report replace that claim for this package.

## V02. Adoption measurement

Use paired fixtures with the same model, starting repository, task intent, and
context budget. Compare legacy Hashline and new profiles without changing style
mid-run. Label parse errors, missing evidence, history gaps, true conflicts,
NoChange, replay, and I/O outcomes separately.

Report verified edit completion, wrong-target writes, preserved concurrent changes,
repair calls, tokens/cost per verified edit, p50/p95 tool latency, and peak whole-
host RSS. Do not count replay/no_change as a newly applied edit or claim improved
success rates before measurement.
